# 5장. 컨테이너 데이터 관리

---

## Volume · Bind Mount · `-mount` · docker cp

> 이 장의 핵심 메시지
>
> **“컨테이너는 데이터를 보관하는 대상이 아니다.”**
>
> 데이터는 반드시 **컨테이너 외부로 분리**해야 한다.

---

## 5장 학습 목표

* 컨테이너의 **쓰기 레이어 한계**를 설명할 수 있다.

* Docker Volume과 Bind Mount의 **차이와 용도**를 구분할 수 있다.

* `v`와 `-mount` 옵션의 **차이와 권장 사용법**을 설명할 수 있다.

* Volume의 **초기화 동작**을 정확히 이해한다.

* `docker cp`를 **언제 써야 하고 언제 쓰면 안 되는지** 설명할 수 있다.

* Stateful 컨테이너(DB 등)의 기본 데이터 설계를 이해한다.

---

## 5.1 컨테이너의 데이터 문제 (왜 이 장이 필요한가)

### 5.1.1 컨테이너의 쓰기 레이어 구조

컨테이너는 다음 구조로 동작한다.

```
[ Image Layers (Read Only) ]
[ Container Writable Layer ]
```

* 컨테이너 실행 시 **쓰기 레이어 1개** 생성

* 컨테이너 삭제 시 → **쓰기 레이어도 함께 삭제**

👉 즉,

> 컨테이너 내부에 저장한 데이터는
>
> 컨테이너 생명주기와 함께 사라진다.

---

### 5.1.2 실무에서 바로 문제가 되는 사례

* DB 컨테이너 재배포 → 데이터 유실

* 웹 로그 컨테이너 재시작 → 로그 증발

* 사용자 업로드 파일 → 컨테이너 삭제와 함께 소멸

👉 그래서 **데이터는 반드시 컨테이너 밖에 저장**해야 한다.

---

## 5.2 Docker의 데이터 관리 방식 개요

Docker는 컨테이너 데이터를 외부로 관리하기 위해

다음 3가지 방법을 제공한다.

| 방식 | 용도 | 지속성 |
| --- | --- | --- |
| Volume | 운영 표준 | ⭕ |
| Bind Mount | 개발/테스트 | ⭕ |
| docker cp | 임시/응급 | ❌ |

---

## 5.3 Docker Volume (운영 환경의 표준)

### 5.3.1 Volume이란?

**Docker Volume**은

👉 Docker가 직접 관리하는 **컨테이너 외부 저장소**다.

* 컨테이너 수명과 분리

* Docker가 저장 위치 관리

* 여러 컨테이너에서 공유 가능

---

### 5.3.2 Volume 저장 위치

```
/var/lib/docker/volumes/
```

⚠️ 주의

* 직접 접근·수정 ❌

* 반드시 Docker 명령으로 관리

---

### 5.3.3 Volume 생성 및 확인

```
docker volume create myvol
docker volume ls
docker volume inspect myvol
```

---

### 5.3.4 Volume 연결 (권장 방식: --mount)

```
docker run -d \
  --name web01 \
  --mount type=volume,source=myvol,target=/usr/share/nginx/html \
  nginx
```

### 옵션 해설

* `type=volume` : Docker Volume 사용

* `source=myvol` : 볼륨 이름

* `target=...` : 컨테이너 내부 경로

👉 **명시적이고 실수 가능성이 낮아 실무 권장**

---

## 5.4 Volume 초기화 동작 (매우 중요)

### 5.4.1 Volume이 비어 있을 때

* 컨테이너 내부 디렉터리에 **기존 파일이 있으면**

* 그 파일들이 **Volume으로 자동 복사됨**

👉 nginx, mysql 이미지에서 매우 중요

---

### 5.4.2 Volume에 데이터가 이미 있을 때

* 컨테이너 내부 파일은 **무시**

* Volume의 기존 데이터 그대로 사용

---

> “Volume은 덮어쓰지 않는다.
>
> **비어 있으면 채우고, 차 있으면 그대로 쓴다.**”

---

## 5.5 Bind Mount (개발·테스트용)

### 5.5.1 Bind Mount란?

Bind Mount는

👉 **호스트의 실제 디렉터리를 컨테이너에 직접 연결**하는 방식이다.

---

### 5.5.2 Bind Mount 사용 예

```
docker run -d \
  --name web02 \
  --mount type=bind,source=/home/user/web,target=/usr/share/nginx/html \
  nginx
```

### 특징

* 파일 변경 즉시 반영

* 개발 환경에서 매우 편리

* 호스트 경로 의존성 큼

---

### 5.5.3 Volume vs Bind Mount 비교

| 항목 | Volume | Bind Mount |
| --- | --- | --- |
| 관리 주체 | Docker | 사용자 |
| 이식성 | 높음 | 낮음 |
| 운영 안정성 | 높음 | 낮음 |
| 권장 환경 | 운영 | 개발 |

---

## 5.6 -v vs `--mount` (명확한 구분)

### 5.6.1 -v (축약형)

```
-v myvol:/data
```

* 짧고 빠름

* 옵션 의미가 불명확

* 실수 발생 가능

---

### 5.6.2 --mount (명시형, 권장)

```
--mount type=volume,source=myvol,target=/data
```

👉 **실무 / 공식 문서 / Kubernetes 개념과도 일관**

---

## 5.7 읽기 전용(Read-only) 마운트

### 왜 필요한가?

* 실수 방지

* 보안 강화

* 운영 안정성

```
docker run -d \
  --mount type=volume,source=myvol,target=/data,readonly \
  nginx
```

👉 코드 디렉터리는 읽기 전용, 로그 디렉터리만 쓰기 허용 같은 설계 가능

---

## 5.8 Named Volume vs Anonymous Volume

### 5.8.1 차이점

| 구분 | Named Volume | Anonymous Volume |
| --- | --- | --- |
| 이름 | 있음 | 없음 |
| 관리 | 쉬움 | 어려움 |
| prune 대상 | ❌ | ⭕ |
| 운영 권장 | ⭕ | ❌ |

```
-v myvol:/data    # named
-v /data          # anonymous
```

👉 **운영에서는 anonymous volume 사용 지양**

---

## 5.9 Volume 공유 (다중 컨테이너)

```
docker volume create sharedvol

docker run -d --name c1 \
  --mount type=volume,source=sharedvol,target=/data \
  ubuntu sleep infinity

docker run -it --name c2 \
  --mount type=volume,source=sharedvol,target=/data \
  ubuntu bash
```

👉 데이터는 **컨테이너 소유물이 아님**을 체감

---

## 5.10 docker cp (임시·응급용 도구)

### 5.10.1 docker cp란?

컨테이너 ↔ 호스트 간 **파일을 직접 복사**하는 명령

---

### 5.10.2 사용 예

```
docker cp web01:/var/log/nginx/access.log ./access.log
docker cp config.conf web01:/etc/nginx/conf.d/
```

---

### 5.10.3 한계와 주의점

* 실시간 동기화 ❌

* 자동 반영 ❌

* 지속 저장 ❌

👉 **설계용 ❌ / 응급 대응용 ⭕**

---

## 5.11 Stateful 컨테이너 설계 원칙

### Stateless

* 웹 서버, API

* 컨테이너 교체 자유로움

### Stateful

* DB, 캐시

* **반드시 Volume 사용**

* 컨테이너 삭제 ≠ 데이터 삭제

---

## 5.12 Volume 정리(prune)

```
docker volume prune
```

* 사용되지 않는 volume만 삭제

* 실행 중인 컨테이너 영향 없음
