# 10-1. SAN 포함 인증서 실습

---

 [[HTTPS]] 

## SAN 인증서란?

SAN = **Subject Alternative Name**

즉,

> 하나의 인증서에 여러 도메인 이름을 포함할 수 있게 해주는 확장 필드

예전에는 CN(Common Name)에 도메인을 하나만 넣었음.

하지만 지금은 **CN은 거의 무시되고 SAN이 필수**임.

## 1. 실습 목표

* app1.local

* app2.local

두 도메인을 **하나의 TLS 인증서**로 HTTPS 적용

---

## 2. SAN 포함 Self-Signed 인증서 생성

### 2.1 SAN 설정 파일 생성

```
cat > san.cnf <<'EOF'
[ req ]
default_bits       = 2048
prompt             = no
default_md         = sha256
distinguished_name = dn
x509_extensions    = v3_req

[ dn ]
C  = KR
ST = Seoul
L  = Seoul
O  = Example
CN = app1.local

[ v3_req ]
subjectAltName = @alt_names

[ alt_names ]
DNS.1 = app1.local
DNS.2 = app2.local
EOF
```

설명:

* CN은 대표 도메인 하나

* SAN에 실제 유효 도메인들을 나열

* 브라우저는 SAN을 기준으로 검증

---

### 2.2 인증서 생성

```
openssl req -x509 -nodes -days 365 \
-newkey rsa:2048 \
-keyout san.key \
-out san.crt \
-config san.cnf
```

2.3 명령으로 인증서 생성

```
# tls.key(비밀키)와 tls.crt(인증서) 생성
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout san.key -out san.crt \
  -subj "/CN=app1.local/O=k8s-lab" \
  -addext "subjectAltName = DNS:app1.local, DNS:app2.local"
```

---

### 2.3 SAN 확인

```
openssl x509 -in san.crt -text -noout | grep -A1 "Subject Alternative Name"
```

출력 예:

```
DNS:app1.local, DNS:app2.local
```

---

## 3. Kubernetes TLS Secret 생성

```
kubectl create secret tls san-tls \
  --cert=san.crt \
  --key=san.key
```

확인:

```
kubectl get secret
```

---

## 4. Ingress 수정 (SAN 인증서 적용)

```
kubectl edit ingress example-ingress
```

추가:

```
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - app1.local
    - app2.local
    secretName: san-tls
```

중요:

* tls.hosts는 SAN 목록과 일치해야 함

* Secret 이름 오타 나면 404 아님 → TLS 에러 발생

## 6. HTTPS 테스트

브라우저:

```
https://app1.local
https://app2.local
```

Self-signed이므로 경고 발생 → 무시 후 접속

## 7. SAN 방식 특징 정리

✔ 서로 다른 루트 도메인도 가능

✔ 정확히 필요한 도메인만 포함

❌ 도메인 추가 시 인증서 재발급 필요
