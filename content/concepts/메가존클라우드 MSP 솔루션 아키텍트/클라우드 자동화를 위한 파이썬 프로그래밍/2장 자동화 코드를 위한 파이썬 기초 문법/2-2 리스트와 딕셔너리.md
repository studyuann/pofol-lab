# 2-2. 리스트와 딕셔너리

* 리스트의 개념을 설명할 수 있다.

* 딕셔너리의 개념을 설명할 수 있다.

* 리스트와 딕셔너리가 결합된 구조를 읽을 수 있다.

* 자동화 코드에서 자주 보이는 중첩 구조를 해석할 수 있다.

## 1. 리스트란 무엇인가

리스트는 **여러 값을 순서대로 저장하는 자료형**이다.

하나의 변수에 값을 하나만 넣는 것이 아니라, 여러 값을 묶어서 저장할 때 사용한다.

예를 들어 여러 AWS 서비스 이름을 하나의 변수에 저장하고 싶다면 리스트를 사용하면 된다.

```
services = ["EC2", "S3", "IAM", "CloudWatch"]
print(services)
```

실행 결과

```
['EC2', 'S3', 'IAM', 'CloudWatch']
```

리스트는 대괄호 `[]`로 만든다.

리스트 안의 값들은 쉼표 `,`로 구분한다.

---

## 2. 리스트에서 값 꺼내기

리스트는 순서가 있기 때문에 **위치 번호**를 사용해 값을 꺼낼 수 있다.

이 위치 번호를 **인덱스(index)** 라고 한다.

중요한 점은 첫 번째 값의 번호가 `1`이 아니라 `0` 이라는 점이다.

```
services = ["EC2", "S3", "IAM", "CloudWatch"]

print(services[0])
print(services[1])
print(services[2])
print(services[3])
```

실행 결과

```
EC2
S3
IAM
CloudWatch
```

즉,

* `services[0]` → 첫 번째 값

* `services[1]` → 두 번째 값

* `services[2]` → 세 번째 값

이다.

---

## 3. 리스트 길이 구하기

리스트 안에 값이 몇 개 들어 있는지 확인할 때는 `len()` 함수를 사용한다.

```
services = ["EC2", "S3", "IAM", "CloudWatch"]
print(len(services))
```

실행 결과

```
4
```

이 값은 리스트의 전체 길이이다.

---

## 4. 리스트에 값 추가하기

리스트에 새 값을 추가할 때는 `append()`를 사용한다.

```
services = ["EC2", "S3", "IAM"]
services.append("Bedrock")

print(services)
```

실행 결과

```
['EC2', 'S3', 'IAM', 'Bedrock']
```

`append()`는 리스트의 **맨 뒤**에 값을 추가한다.

---

## 5. 리스트를 반복문으로 처리하기

리스트는 반복문과 함께 자주 사용한다.

자동화 코드에서는 여러 인스턴스, 여러 버킷, 여러 로그 라인을 순서대로 처리해야 하는 경우가 많기 때문이다.

```
services = ["EC2", "S3", "IAM", "CloudWatch"]

for service in services:
    print(service)
```

실행 결과

```
EC2
S3
IAM
CloudWatch
```

여기서 `service`는 반복문이 한 번 돌 때마다 리스트 안의 값을 하나씩 받아오는 변수이다.

이 구조는 이후 거의 계속 등장한다.

## 6. 딕셔너리란 무엇인가

딕셔너리는 **키(key)와 값(value)의 쌍으로 데이터를 저장하는 자료형**이다.

리스트가 순서 중심이라면, 딕셔너리는 이름 중심이라고 보면 된다.

예를 들어 인스턴스 하나의 정보를 저장하고 싶다고 해보자.

* 인스턴스 ID

* 상태

* 타입

* 이름

이런 정보는 딕셔너리로 표현하기 좋다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running",
    "InstanceType": "t3.micro",
    "Name": "web-1"
}

print(instance)
```

실행 결과

```
{'InstanceId': 'i-1234567890abcdef0', 'State': 'running', 'InstanceType': 't3.micro', 'Name': 'web-1'}
```

딕셔너리는 중괄호 `{}`로 만든다.

각 항목은 `키: 값` 형태로 작성한다.

---

## 7. 딕셔너리에서 값 꺼내기

딕셔너리에서는 인덱스가 아니라 **키 이름**을 사용해서 값을 꺼낸다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running",
    "InstanceType": "t3.micro",
    "Name": "web-1"
}

print(instance["InstanceId"])
print(instance["State"])
print(instance["InstanceType"])
print(instance["Name"])
```

실행 결과

```
i-1234567890abcdef0
running
t3.micro
web-1
```

리스트는 `[0]`, `[1]`처럼 위치로 꺼냈고,

딕셔너리는 `["InstanceId"]`, `["State"]`처럼 이름으로 꺼낸다.

이 차이를 분명히 구분해야 한다.

---

## 8. 딕셔너리에 값 추가하기

딕셔너리에 새로운 키와 값을 추가할 수 있다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running"
}

instance["Name"] = "web-1"
instance["PrivateIp"] = "10.0.1.15"

print(instance)
```

실행 결과

```
{'InstanceId': 'i-1234567890abcdef0', 'State': 'running', 'Name': 'web-1', 'PrivateIp': '10.0.1.15'}
```

---

## 9. 딕셔너리에서 `get()` 사용하기

딕셔너리에서 없는 키를 바로 조회하면 오류가 날 수 있다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running"
}

# print(instance["Name"])
```

위 코드는 `Name` 키가 없으면 오류가 난다.

그래서 자동화 코드에서는 `get()`을 많이 사용한다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running"
}

print(instance.get("Name"))
```

실행 결과

```
None
```

키가 없으면 `None`을 반환한다.

기본값도 지정할 수 있다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": "running"
}

print(instance.get("Name", "NoName"))
```

실행 결과

```
NoName
```

이 방식은 AWS 태그 조회에서 매우 자주 사용된다.

## 10. 중첩 딕셔너리

실제 자동화 코드에서는 딕셔너리 안에 또 다른 딕셔너리가 들어가는 경우가 많다.

예를 들어 인스턴스 상태를 아래처럼 표현할 수 있다.

```
instance = {
    "InstanceId": "i-1234567890abcdef0",
    "State": {
        "Name": "running"
    }
}

print(instance["State"]["Name"])
```

실행 결과

```
running
```

여기서 구조를 잘 봐야 한다.

* `instance["State"]` → `{"Name": "running"}`

* `instance["State"]["Name"]` → `"running"`

즉, 한 번에 끝나는 구조가 아니라 **한 단계 더 들어가는 구조**이다.

이 패턴은 `boto3` 응답에서 아주 흔하다.

---

## 11. 리스트와 딕셔너리의 결합

이제부터가 중요하다.

실제 자동화 코드에서는 리스트와 딕셔너리가 따로 등장하기보다 **결합된 구조**로 많이 나온다.

예를 들어 여러 인스턴스를 저장하면 아래처럼 표현할 수 있다.

```
instances = [
    {"InstanceId": "i-1111", "State": "running", "Name": "web-1"},
    {"InstanceId": "i-2222", "State": "stopped", "Name": "db-1"},
    {"InstanceId": "i-3333", "State": "running", "Name": "app-1"}
]

print(instances)
```

이 구조는

* 바깥쪽은 리스트

* 리스트 안의 각 항목은 딕셔너리

이다.

즉, **여러 개의 객체를 리스트로 묶고**,

**각 객체의 상세 정보는 딕셔너리로 표현**한 것이다.

이 방식은 AWS 응답 구조의 기본 패턴이라고 생각하면 된다.

---

## 12. 리스트 안의 딕셔너리 반복 처리

위 구조를 하나씩 처리하려면 반복문을 사용한다.

```
instances = [
    {"InstanceId": "i-1111", "State": "running", "Name": "web-1"},
    {"InstanceId": "i-2222", "State": "stopped", "Name": "db-1"},
    {"InstanceId": "i-3333", "State": "running", "Name": "app-1"}
]

for instance in instances:
    print(instance["InstanceId"], instance["State"], instance["Name"])
```

실행 결과

```
i-1111 running web-1
i-2222 stopped db-1
i-3333 running app-1
```

여기서 흐름을 정확히 이해해야 한다.

1. `instances`는 리스트이다.

2. 반복문이 한 번 돌 때마다 `instance`에 딕셔너리 하나가 들어간다.

3. 그 딕셔너리에서 `"InstanceId"`, `"State"`, `"Name"` 값을 꺼내는 것이다.

## 13. 조건문과 함께 사용하기

이 구조에 조건문을 추가하면 특정 상태만 골라낼 수 있다.

```
instances = [
    {"InstanceId": "i-1111", "State": "running", "Name": "web-1"},
    {"InstanceId": "i-2222", "State": "stopped", "Name": "db-1"},
    {"InstanceId": "i-3333", "State": "running", "Name": "app-1"}
]

for instance in instances:
    if instance["State"] == "running":
        print(instance["Name"], instance["InstanceId"])
```

실행 결과

```
web-1 i-1111
app-1 i-3333
```

이 구조는 뒤에서 EC2 상태 필터링 코드와 거의 같은 방식으로 등장한다.

## 14. 딕셔너리 안에 리스트가 있는 구조

이번에는 반대 구조를 보자.

딕셔너리 안에 리스트가 들어갈 수도 있다.

```
response = {
    "Services": ["EC2", "S3", "IAM"],
    "Region": "ap-northeast-2"
}

print(response["Region"])
print(response["Services"])
print(response["Services"][0])
```

실행 결과

```
ap-northeast-2
['EC2', 'S3', 'IAM']
EC2
```

구조를 보면 다음과 같다.

* `response`는 딕셔너리

* `response["Services"]`는 리스트

* `response["Services"][0]`는 리스트의 첫 번째 값

즉, **한 번은 키로 들어가고**,

**그 다음은 인덱스로 들어가는 구조**이다.

## 15. 실제 자동화 스타일에 가까운 예제

다음 예제를 보자.

```
response = {
    "Reservations": [
        {
            "Instances": [
                {"InstanceId": "i-1111", "State": {"Name": "running"}, "Name": "web-1"},
                {"InstanceId": "i-2222", "State": {"Name": "stopped"}, "Name": "db-1"}
            ]
        }
    ]
}

for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print(instance["InstanceId"], instance["State"]["Name"], instance["Name"])
```

실행 결과

```
i-1111 running web-1
i-2222 stopped db-1
```

이 구조는 `boto3`의 EC2 응답과 매우 비슷하다.

처음 보면 복잡해 보이지만 순서대로 보면 된다.

### 구조 해석 순서

### 1) `response`는 딕셔너리

```
response["Reservations"]
```

이 값은 리스트이다.

### 2) `response["Reservations"]`는 리스트

반복문으로 하나씩 꺼내야 한다.

```
for reservation in response["Reservations"]:
```

여기서 `reservation`은 딕셔너리이다.

### 3) `reservation["Instances"]`는 리스트

이 안에 인스턴스들이 들어 있다.

```
for instance in reservation["Instances"]:
```

여기서 `instance`는 딕셔너리이다.

### 4) 인스턴스 상세 값 조회

```
instance["InstanceId"]
instance["State"]["Name"]
instance["Name"]
```

즉, **딕셔너리 → 리스트 → 딕셔너리 → 리스트 → 딕셔너리** 구조를 단계적으로 따라가고 있는 것이다.

## 실습 4. 중첩 구조 읽기

파일명: `nested_structure.py`

```
response = {
    "Reservations": [
        {
            "Instances": [
                {"InstanceId": "i-1111", "State": {"Name": "running"}, "Name": "web-1"},
                {"InstanceId": "i-2222", "State": {"Name": "stopped"}, "Name": "db-1"},
                {"InstanceId": "i-3333", "State": {"Name": "running"}, "Name": "app-1"}
            ]
        }
    ]
}

print("전체 인스턴스 출력")

    for instance in reservation["Instances"]:
```

* `instance["State"]["Name"]`처럼 한 단계 더 들어가는 조회 방식을 확인한다.

* `running` 상태 필터링이 잘 되는지 확인한다.

## 16. `get()`을 활용한 안전한 조회

자동화 코드에서는 어떤 값이 항상 존재한다고 가정하면 안 될 때가 많다.

예를 들어 이름 태그가 없을 수도 있다.

```
instances = [
    {"InstanceId": "i-1111", "State": "running", "Name": "web-1"},
    {"InstanceId": "i-2222", "State": "stopped"},
    {"InstanceId": "i-3333", "State": "running", "Name": "app-1"}
]

for instance in instances:
    print(instance.get("Name", "NoName"))
```

실행 결과

```
web-1
NoName
app-1
```

## 17. 자동화 코드 스타일 종합 실습

이제 지금까지 배운 내용을 바탕으로 자동화 스타일 예제를 만들어 본다.

파일명: `instance_report.py`

```
instances = [
    {"InstanceId": "i-1111", "State": "running", "Name": "web-1", "Cpu": 32.5},
    {"InstanceId": "i-2222", "State": "stopped", "Name": "db-1", "Cpu": 0.0},
    {"InstanceId": "i-3333", "State": "running", "Name": "app-1", "Cpu": 67.8},
    {"InstanceId": "i-4444", "State": "running", "Cpu": 81.2}
]

print("전체 인스턴스 목록")
for instance in instances:
    print(
        f"name={instance.get('Name', 'NoName')}, "
        f"id={instance['InstanceId']}, "
        f"state={instance['State']}, "
        f"cpu={instance['Cpu']}"
    )

print("\nrunning 상태 인스턴스")
for instance in instances:
    if instance["State"] == "running":
        print(
            f"name={instance.get('Name', 'NoName')}, "
            f"id={instance['InstanceId']}, "
            f"cpu={instance['Cpu']}"
        )

print("\nCPU 사용률 60 초과 인스턴스")
for instance in instances:
    if instance["Cpu"] > 60:
        print(
            f"name={instance.get('Name', 'NoName')}, "
            f"id={instance['InstanceId']}, "
            f"cpu={instance['Cpu']}"
        )
```

### 학습 포인트

이 실습에는 다음 내용이 모두 들어 있다.

* 리스트

* 딕셔너리

* `get()`

* 반복문

* 조건문

* f-string

* 필터링

즉, 이후 AWS 자동화 코드와 매우 비슷한 형태라고 볼 수 있다.

## 18. 자주 하는 실수

### 1) 리스트를 딕셔너리처럼 접근하는 경우

```
services = ["EC2", "S3", "IAM"]
# print(services["EC2"])
```

리스트는 키가 아니라 인덱스로 접근해야 한다.

정상 예시

```
print(services[0])
```

---

### 2) 딕셔너리를 리스트처럼 접근하는 경우

```
instance = {"InstanceId": "i-1111", "State": "running"}
# print(instance[0])
```

딕셔너리는 인덱스가 아니라 키로 접근해야 한다.

정상 예시

```
print(instance["InstanceId"])
```

---

### 3) 없는 키를 바로 조회하는 경우

```
instance = {"InstanceId": "i-1111"}
# print(instance["Name"])
```

이 경우 오류가 날 수 있다.

가능하면 `get()` 사용을 함께 익히는 것이 좋다.

---

### 4) 중첩 구조에서 단계 하나를 빼먹는 경우

```
instance = {
    "State": {
        "Name": "running"
    }
}

# print(instance["Name"])
```

정상 예시

```
print(instance["State"]["Name"])
```

## 19. 정리

* 리스트는 여러 값을 순서대로 저장한다.

* 리스트는 인덱스로 값을 꺼낸다.

* 딕셔너리는 키와 값의 쌍으로 데이터를 저장한다.

* 딕셔너리는 키 이름으로 값을 조회한다.

* `get()`은 없는 키를 안전하게 처리할 때 유용하다.

* 실제 자동화 코드에서는 리스트와 딕셔너리가 결합된 구조가 매우 많다.

* AWS API 응답은 중첩된 리스트/딕셔너리 구조가 자주 등장한다.

* 반복문과 조건문을 함께 사용하면 원하는 데이터만 필터링할 수 있다.
