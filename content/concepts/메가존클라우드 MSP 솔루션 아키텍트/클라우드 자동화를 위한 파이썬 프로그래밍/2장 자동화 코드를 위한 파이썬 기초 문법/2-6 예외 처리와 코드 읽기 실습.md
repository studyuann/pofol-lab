# 2-6. 예외 처리와 코드 읽기 실습

## 학습 목표

* 예외의 의미를 설명할 수 있다.

* `try`, `except` 구문의 기본 구조를 설명할 수 있다.

* 실행 중 오류가 발생했을 때 기본적인 오류 메시지를 출력할 수 있다.

* 파일이 없을 때 예외를 처리할 수 있다.

* 딕셔너리에 없는 키를 다룰 때 발생할 수 있는 문제를 이해할 수 있다.

* 자동화 스타일 예제 코드를 읽고 동작 흐름을 설명할 수 있다.

* 코드에서 어떤 부분을 수정하면 원하는 결과가 바뀌는지 파악할 수 있다.

## 1. 예외란 무엇인가

프로그램을 실행하다 보면 예상하지 못한 문제가 발생할 수 있다.

예를 들면 다음과 같은 경우이다.

* 열려고 한 파일이 존재하지 않음

* 숫자로 바꿔야 하는 값을 숫자로 바꿀 수 없음

* 딕셔너리에 없는 키를 조회함

* 사용자가 잘못된 입력값을 넣음

이렇게 **실행 중 발생하는 오류 상황**을 예외라고 한다.

예외 처리를 하지 않으면 프로그램은 그 지점에서 바로 중단될 수 있다.

자동화 코드에서는 이런 상황이 자주 생기므로, 예외 처리는 매우 중요하다.

---

## 2. 왜 예외 처리가 필요한가

자동화 코드는 사람이 직접 모든 상황을 통제할 수 없는 환경에서 자주 실행된다.

예를 들어

* 파일이 삭제되었을 수 있음

* JSON 설정 파일 구조가 예상과 다를 수 있음

* 일부 데이터에 값이 비어 있을 수 있음

* 키 이름이 빠져 있을 수 있음

* 로그 파일 안의 줄 형식이 일정하지 않을 수 있음

이런 상황에서 프로그램이 무조건 중단되면 실습도 끊기고, 실제 운영 자동화도 불안정해진다.

그래서 오류를 발견했을 때 **원인을 확인하고 적절히 대응하는 구조**가 필요하다.

---

# 3. try / except 기본 구조

예외 처리는 보통 `try`와 `except`를 사용한다.

기본 구조는 다음과 같다.

```
try:
    실행할 코드
except:
    오류가 발생했을 때 실행할 코드
```

이 구조의 의미는 다음과 같다.

* `try` 블록 안의 코드를 먼저 실행한다.

* 만약 오류가 발생하면 `except` 블록으로 이동한다.

* 오류가 없으면 `except`는 실행되지 않는다.

---

## 4. 가장 간단한 예외 처리 예제

```
try:
    number = int("abc")
except:
    print("숫자 변환 중 오류 발생")
```

실행 결과

```
숫자 변환 중 오류 발생
```

여기서는 `"abc"`를 숫자로 바꾸려고 했기 때문에 오류가 발생했다.

하지만 예외 처리를 했기 때문에 프로그램이 바로 중단되지 않고, 지정한 메시지를 출력했다.

---

## 5. 예외 메시지까지 확인하기

오류가 발생했다는 사실만 보는 것보다, **무슨 오류인지** 함께 보는 것이 더 중요하다.

이를 위해 `except Exception as e` 형식을 사용한다.

```
try:
    number = int("abc")
except Exception as e:
    print("오류 발생")
    print(e)
```

실행 결과 예시

```
오류 발생
invalid literal for int() with base 10: 'abc'
```

여기서 `e`에는 실제 오류 메시지가 들어 있다.

이 구조는 실습 중 디버깅할 때 매우 자주 사용한다.

## 실습 1. 숫자 변환 오류 처리

파일명: `try_number.py`

```
value = "abc"

try:
    number = int(value)
    print(number)
except Exception as e:
    print("숫자 변환 실패")
    print(f"오류 내용: {e}")
```

### 확인할 내용

* 오류가 발생해도 프로그램이 바로 중단되지 않는지 확인한다.

* 오류 메시지가 함께 출력되는지 확인한다.

## 6. 파일이 없을 때 발생하는 오류

파일을 읽을 때 가장 흔한 오류 중 하나는 **파일이 존재하지 않는 경우**이다.

```
with open("not_found.txt", "r", encoding="utf-8") as file:
    content = file.read()
```

이 코드는 `not_found.txt` 파일이 없으면 오류가 발생한다.

예외 처리로 감싸면 다음과 같이 바꿀 수 있다.

```
try:
    with open("not_found.txt", "r", encoding="utf-8") as file:
        content = file.read()
        print(content)
except Exception as e:
    print("파일 읽기 실패")
    print(f"오류 내용: {e}")
```

실행 결과 예시

```
파일 읽기 실패
오류 내용: [Errno 2] No such file or directory: 'not_found.txt'
```

### 확인할 내용

* 파일이 없을 때 오류 메시지가 출력되는지 확인한다.

* `filename` 값을 바꾸면 다른 파일을 읽을 수 있는지 확인한다.

---

## 7. 딕셔너리에 없는 키를 조회할 때

딕셔너리에서 존재하지 않는 키를 바로 읽으려고 하면 오류가 날 수 있다.

```
instance = {
    "InstanceId": "i-1111",
    "State": "running"
}

print(instance["Name"])
```

이 코드는 `"Name"` 키가 없기 때문에 오류가 발생한다.

예외 처리로 감싸면 다음과 같다.

```
instance = {
    "InstanceId": "i-1111",
    "State": "running"
}

try:
    print(instance["Name"])
except Exception as e:
    print("키 조회 중 오류 발생")
    print(f"오류 내용: {e}")
```

실행 결과 예시

```
키 조회 중 오류 발생
오류 내용: 'Name'
```

다만 이런 경우는 예외 처리도 가능하지만, 앞 절에서 배운 `get()`을 사용하는 방식이 더 자연스러운 경우가 많다.

```
instance = {
    "InstanceId": "i-1111",
    "State": "running"
}

print(instance.get("Name", "NoName"))
```

실행 결과

```
NoName
```

즉,

* 정말 오류 상황을 잡고 싶을 때는 `try/except`

* 키가 없을 수도 있는 상황을 자연스럽게 처리할 때는 `get()`

이라고 이해하면 된다.

## 실습 2. 딕셔너리 키 오류 확인

파일명: `try_key.py`

### 확인할 내용

* `[]` 접근과 `get()` 접근의 차이를 확인한다.

* 같은 상황에서도 처리 방식이 다를 수 있음을 이해한다.

## 8. 숫자 변환과 입력 데이터 오류

자동화 코드에서는 문자열로 들어온 값을 숫자로 바꿔야 하는 경우가 있다.

이때 값이 숫자 형식이 아니면 오류가 발생할 수 있다.

```
cpu_text = "91.5"
cpu_usage = float(cpu_text)
print(cpu_usage)
```

이 경우는 정상 동작한다.

하지만 아래처럼 숫자가 아니면 오류가 난다.

```
cpu_text = "high"
cpu_usage = float(cpu_text)
print(cpu_usage)
```

예외 처리로 감싸면 다음과 같다.

```
cpu_text = "high"

try:
    cpu_usage = float(cpu_text)
    print(cpu_usage)
except Exception as e:
    print("CPU 값 변환 실패")
    print(f"오류 내용: {e}")
```

## 9. 자동화 코드에서 자주 보는 예외 처리 패턴

자동화 코드에서는 예외 처리가 보통 다음 위치에 들어간다.

### 1) 파일 읽기

설정 파일, 로그 파일, 결과 파일을 열 때

### 2) JSON 읽기

설정 파일 형식이 잘못되었을 때

### 3) 키 조회

일부 데이터에 값이 없을 때

### 4) 값 변환

숫자 변환, 형식 변환이 실패할 때

### 5) 외부 API 호출

이후 boto3에서 AWS API 호출 시에도 예외 처리가 중요해진다

즉, 예외 처리는 이번 절에서 끝나는 내용이 아니라, 이후 전 장에서 계속 반복해서 쓰이게 된다.

# 10. 코드 읽기 실습이 필요한 이유

이 과정에서는 처음부터 직접 작성하는 방식보다,

**생성형 AI가 만든 코드를 읽고 수정하는 방식**이 더 중요하다.

그렇다면 코드를 읽을 때 어떤 순서로 봐야 하는지를 알아야 한다.

보통 자동화 코드는 아래 순서로 보면 이해하기 쉽다.

1. 어떤 데이터가 들어 있는가

2. 어떤 함수가 정의되어 있는가

3. 반복문이 있는가

4. 조건문이 있는가

5. 파일을 읽거나 저장하는가

6. 예외 처리가 있는가

7. 최종적으로 무엇을 출력하는가

이 절에서는 이 기준으로 자동화 스타일 예제를 읽는 연습을 한다.

# 11. 자동화 스타일 코드 읽기 예제 1

다음 코드를 보자.

```
instances = [
    {"InstanceId": "i-1111", "Name": "web-1", "State": "running"},
    {"InstanceId": "i-2222", "Name": "db-1", "State": "stopped"},
    {"InstanceId": "i-3333", "State": "app-1", "State": "running"}
]

for instance in instances:
    if instance["State"] == "running":
        print(f"{instance['Name']} - {instance['InstanceId']}")
```

이 코드를 읽는 순서는 다음과 같다.

### 1) `instances`는 리스트이다

리스트 안에 딕셔너리 3개가 들어 있다.

### 2) 반복문이 있다

`for instance in instances:`

즉, 인스턴스를 하나씩 꺼낸다.

### 3) 조건문이 있다

`if instance["State"] == "running":`

즉, running 상태만 선택한다.

### 4) 출력한다

이름과 인스턴스 ID를 출력한다.

즉, 이 코드는 **running 상태인 인스턴스만 골라서 이름과 ID를 출력하는 코드**이다.

# 12. 자동화 스타일 코드 읽기 예제 2

이번에는 함수가 포함된 구조를 보자.

```
def print_instance_info(instance):
    print(
        f"name={instance.get('Name', 'NoName')}, "
        f"state={instance['State']}"
    )

instances = [
    {"Name": "web-1", "State": "running"},
    {"State": "stopped"},
    {"Name": "app-1", "State": "running"}
]

for instance in instances:
    print_instance_info(instance)
```

이 코드는 다음과 같이 읽는다.

### 1) 함수가 먼저 정의되어 있다

`print_instance_info(instance)`

인스턴스 하나를 받아서 이름과 상태를 출력하는 함수이다.

### 2) `get()`을 사용한다

`Name` 키가 없는 경우에도 `"NoName"`으로 처리할 수 있도록 했다.

### 3) 인스턴스 목록이 있다

세 개의 딕셔너리가 들어 있고, 두 번째 항목은 `Name` 키가 없다.

### 4) 반복문으로 하나씩 함수에 전달한다

즉, 모든 항목을 출력하되, 키가 없는 상황도 안전하게 처리한다.

# 14. 예외 처리와 코드 수정 연결하기

이제 예외 처리와 코드 읽기를 함께 연결해보자.

예를 들어 아래 코드를 보자.

```
instances = [
    {"Name": "web-1", "State": "running"},
    {"State": "stopped"},
    {"Name": "app-1", "State": "running"}
]

for instance in instances:
    print(instance["Name"])
```

이 코드는 두 번째 항목에 `Name` 키가 없기 때문에 오류가 날 수 있다.

이럴 때 수정 방법은 두 가지가 있다.

### 1) 예외 처리 추가

```
instances = [
    {"Name": "web-1", "State": "running"},
    {"State": "stopped"},
    {"Name": "app-1", "State": "running"}
]

for instance in instances:
    try:
        print(instance["Name"])
    except Exception as e:
        print("이름 출력 중 오류 발생")
        print(e)
```

### 2) get()으로 구조 개선

```
instances = [
    {"Name": "web-1", "State": "running"},
    {"State": "stopped"},
    {"Name": "app-1", "State": "running"}
]

for instance in instances:
    print(instance.get("Name", "NoName"))
```

두 방식 모두 쓸 수 있다.

다만 단순히 키가 없을 가능성이 있는 상황은 `get()`이 더 자연스럽고,

예상하지 못한 오류 상황을 전체적으로 잡고 싶을 때는 `try/except`가 더 적절하다.

# 15. 자동화 스타일 종합 예제

이제 지금까지 배운 내용을 한 예제에 모아보자.

파일명: `exception_summary.py`

```
import json

def load_config(filename):
    try:
        with open(filename, "r", encoding="utf-8") as file:
            return json.load(file)
    except Exception as e:
        print("설정 파일 읽기 실패")
        print(f"오류 내용: {e}")
        return None

def print_services(config):
    try:
        for service in config["services"]:
            print(f"service: {service}")
    except Exception as e:
        print("서비스 목록 출력 실패")
        print(f"오류 내용: {e}")

config = load_config("config.json")

if config:
    print_services(config)
```

### 코드 해석

### 1) `json` 모듈을 가져온다

JSON 파일을 읽기 위해 필요하다.

### 2) `load_config()` 함수

설정 파일을 읽는 함수이다.

오류가 나면 메시지를 출력하고 `None`을 반환한다.

### 3) `print_services()` 함수

설정 파일 안의 `services` 목록을 출력한다.

만약 `services` 키가 없거나 구조가 다르면 오류를 잡는다.

### 4) 메인 흐름

* `config.json`을 읽는다.

* 정상적으로 읽혔으면 서비스 목록을 출력한다.

즉, 이 코드는 **설정 파일 읽기 + 예외 처리 + 함수 사용 + 리스트 반복 처리**를 함께 포함하는 자동화 스타일 예제이다.

# 16. 정리

* 예외는 실행 중 발생하는 오류 상황이다.

* `try/except`를 사용하면 오류가 발생해도 프로그램이 바로 중단되지 않도록 만들 수 있다.

* `except Exception as e` 형태를 사용하면 실제 오류 메시지를 함께 확인할 수 있다.

* 파일 읽기, 키 조회, 숫자 변환은 예외가 자주 발생하는 대표적인 상황이다.

* 자동화 코드에서는 예외 처리가 매우 중요하다.

* 코드를 읽을 때는 데이터 구조, 반복문, 조건문, 함수, 파일 처리, 예외 처리 순서로 보면 이해하기 쉽다.

* 단순히 오류를 피하는 것이 아니라, 코드를 읽고 어디를 수정해야 하는지 파악하는 능력이 중요하다.
