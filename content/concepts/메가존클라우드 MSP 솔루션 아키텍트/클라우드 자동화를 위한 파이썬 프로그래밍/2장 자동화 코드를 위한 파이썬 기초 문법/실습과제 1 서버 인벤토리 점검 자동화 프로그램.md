# 실습과제 1. 서버 인벤토리 점검 자동화 프로그램

## 과제 목표

여러 서버 정보를 Python 자료구조로 관리하고, 조건에 따라 서버 상태를 점검한 뒤 결과를 JSON 파일로 저장하는 프로그램을 작성한다.

이 실습에서는 다음 내용을 종합적으로 사용한다.

* 변수와 자료형

* 리스트와 딕셔너리

* 조건문과 반복문

* 함수와 모듈

* 파일 처리

* JSON 처리

* 예외 처리

* tuple

* set

---

## 요구사항

다음 서버 목록을 사용한다.

```
servers = [
    {
        "id": "srv-001",
        "name": "web-1",
        "role": "web",
        "status": "running",
        "cpu": 35,
        "memory": 60,
        "ports": [80, 443]
    },
    {
        "id": "srv-002",
        "name": "web-2",
        "role": "web",
        "status": "stopped",
        "cpu": 0,
        "memory": 0,
        "ports": [80, 443]
    },
    {
        "id": "srv-003",
        "name": "db-1",
        "role": "db",
        "status": "running",
        "cpu": 72,
        "memory": 85,
        "ports": [3306]
    },
    {
        "id": "srv-004",
        "name": "cache-1",
        "role": "cache",
        "status": "running",
        "cpu": 25,
        "memory": 40,
        "ports": [6379]
    }
]
```

---

## 구현 조건

### 1. 서버 상태 점검 함수 작성

다음 함수를 작성한다.

```
def check_server_health(server):
    ...
```

이 함수는 서버 하나를 전달받아 다음 기준으로 상태를 판단한다.

| 조건 | 결과 |
| --- | --- |
| status가 stopped이면 | stopped |
| cpu가 70 이상이거나 memory가 80 이상이면 | warning |
| 그 외 | normal |

반환값은 문자열로 한다.

예시:

```
"normal"
"warning"
"stopped"
```

---

### 2. 서버 요약 정보 생성 함수 작성

다음 함수를 작성한다.

```
def make_server_summary(server):
    ...
```

이 함수는 서버 하나를 전달받아 다음 형식의 딕셔너리를 반환한다.

```
{
    "id": "srv-001",
    "name": "web-1",
    "role": "web",
    "health": "normal"
}
```

`health` 값은 `check_server_health()` 함수를 호출해서 구한다.

---

### 3. 전체 서버 목록을 반복 처리한다

`for` 반복문을 사용해서 전체 서버를 점검한다.

점검 결과는 새로운 리스트에 저장한다.

```
summary_list = []
```

최종 결과 예시는 다음과 같다.

```
[
    {
        "id": "srv-001",
        "name": "web-1",
        "role": "web",
        "health": "normal"
    },
    {
        "id": "srv-002",
        "name": "web-2",
        "role": "web",
        "health": "stopped"
    }
]
```

---

### 4. role 목록을 set으로 추출한다

전체 서버에서 사용 중인 role 목록을 중복 없이 출력한다.

예시 출력:

```
사용 중인 서버 역할:
{'web', 'db', 'cache'}
```

힌트:

```
roles = set()
```

또는 set comprehension을 사용할 수 있다.

```
roles = {server["role"] for server in servers}
```

---

### 5. 점검 기준을 tuple로 관리한다

CPU와 메모리 경고 기준은 tuple로 관리한다.

```
THRESHOLD = (70, 80)
```

의미는 다음과 같다.

```
THRESHOLD[0]  # CPU 경고 기준
THRESHOLD[1]  # Memory 경고 기준
```

`check_server_health()` 함수 내부에서 이 tuple 값을 사용한다.

---

### 6. JSON 파일로 저장한다

점검 결과를 다음 파일명으로 저장한다.

```
server_health_result.json
```

저장할 때는 `json.dump()`를 사용한다.

```
json.dump(data, file, ensure_ascii=False, indent=2)
```

---

### 7. 예외 처리를 추가한다

파일 저장 과정에서 오류가 발생할 수 있으므로 `try ~ except`를 사용한다.

예시 구조:

```
try:
    with open("server_health_result.json", "w", encoding="utf-8") as file:
        json.dump(summary_list, file, ensure_ascii=False, indent=2)
    print("파일 저장 완료")
except Exception as e:
    print("파일 저장 중 오류 발생")
    print(e)
```

사용 중인 서버 역할:

# 실습과제 2. 보안 그룹 규칙 분석 프로그램

## 과제 목표

보안 그룹 규칙 데이터를 분석해서 위험한 규칙을 탐지하고, 결과를 JSON 파일로 저장하는 프로그램을 작성한다.

이 실습은 클라우드 보안 점검 자동화 코드의 기본 형태로 볼 수 있다.

---

## 제공 데이터

```
security_groups = [
    {
        "group_id": "sg-001",
        "group_name": "web-sg",
        "rules": [
            {"protocol": "tcp", "port": 80, "source": "0.0.0.0/0"},
            {"protocol": "tcp", "port": 443, "source": "0.0.0.0/0"},
            {"protocol": "tcp", "port": 22, "source": "10.0.0.0/24"}
        ]
    },
    {
        "group_id": "sg-002",
        "group_name": "admin-sg",
        "rules": [
            {"protocol": "tcp", "port": 22, "source": "0.0.0.0/0"},
            {"protocol": "tcp", "port": 3389, "source": "0.0.0.0/0"}
        ]
    },
    {
        "group_id": "sg-003",
        "group_name": "db-sg",
        "rules": [
            {"protocol": "tcp", "port": 3306, "source": "10.0.1.0/24"},
            {"protocol": "tcp", "port": 5432, "source": "10.0.2.0/24"}
        ]
    }
]
```

---

## 구현 조건

### 1. 위험 포트를 tuple로 정의한다

관리 포트는 외부에 열려 있으면 위험하다고 판단한다.

```
DANGEROUS_PORTS = (22, 3389)
```

의미는 다음과 같다.

| 포트 | 의미 |
| --- | --- |
| 22 | SSH |
| 3389 | RDP |

---

### 2. 외부 공개 대역을 set으로 정의한다

외부 전체 공개 대역은 다음과 같이 관리한다.

```
PUBLIC_SOURCES = {"0.0.0.0/0", "::/0"}
```

`set`을 사용하는 이유는 특정 source 값이 공개 대역에 포함되는지 빠르게 확인하기 위해서다.

```
if source in PUBLIC_SOURCES:
    ...
```

---

### 3. 위험 규칙 판별 함수 작성

다음 함수를 작성한다.

```
def is_dangerous_rule(rule):
    ...
```

이 함수는 보안 그룹 규칙 하나를 전달받아 위험 여부를 판단한다.

위험 조건은 다음과 같다.

```
포트가 22 또는 3389이고, source가 0.0.0.0/0 또는 ::/0이면 위험 규칙이다.
```

반환값은 `True` 또는 `False`로 한다.

예시:

```
rule = {"protocol": "tcp", "port": 22, "source": "0.0.0.0/0"}

result = is_dangerous_rule(rule)
print(result)
```

출력:

```
True
```

---

### 4. 보안 그룹 하나를 분석하는 함수 작성

다음 함수를 작성한다.

```
def analyze_security_group(security_group):
    ...
```

이 함수는 보안 그룹 하나를 전달받아 위험 규칙만 추출한다.

반환 형식은 다음과 같다.

```
{
    "group_id": "sg-002",
    "group_name": "admin-sg",
    "dangerous_rules": [
        {"protocol": "tcp", "port": 22, "source": "0.0.0.0/0"},
        {"protocol": "tcp", "port": 3389, "source": "0.0.0.0/0"}
    ],
    "dangerous_count": 2
}
```

---

### 5. 전체 보안 그룹을 반복 분석한다

전체 `security_groups` 목록을 반복하면서 각 보안 그룹을 분석한다.

분석 결과는 새로운 리스트에 저장한다.

```
analysis_result = []
```

단, 위험 규칙이 하나 이상 있는 보안 그룹만 결과에 포함한다.

즉, `dangerous_count`가 0이면 결과 리스트에 넣지 않는다.

---

### 6. 예외 처리를 추가한다

분석 중 특정 규칙에 `port` 또는 `source` 키가 없을 수도 있다고 가정한다.

`is_dangerous_rule()` 함수 내부에서 예외 처리를 추가한다.

예시 구조:

```
try:
    port = rule["port"]
    source = rule["source"]
except KeyError as e:
    print(f"규칙 데이터에 필요한 키가 없음: {e}")
    return False
```

---

### 7. 결과를 JSON 파일로 저장한다

분석 결과를 다음 파일로 저장한다.

```
security_group_audit_result.json
```

저장할 때는 `json.dump()`를 사용한다.

---

## 실행 결과 예시

```
보안 그룹 분석 결과

[위험] sg-002 admin-sg
- tcp 22 0.0.0.0/0
- tcp 3389 0.0.0.0/0

security_group_audit_result.json 파일 저장 완료
```
