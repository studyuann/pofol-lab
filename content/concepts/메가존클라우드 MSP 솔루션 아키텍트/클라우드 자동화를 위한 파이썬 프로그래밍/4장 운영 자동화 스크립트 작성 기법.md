# 4장. 운영 자동화 스크립트 작성 기법

## 4.1 4장의 목표

3장에서는 `boto3`를 이용해 AWS API를 호출하는 기본 방법을 학습했다.

예를 들어 EC2 인스턴스 목록을 조회하거나, S3 버킷 목록을 확인하거나, IAM 사용자 목록을 조회하는 식이다.

하지만 실무 자동화에서는 단순히 API를 한 번 호출하는 코드만으로는 부족하다.

운영자가 실제로 사용하는 자동화 스크립트는 다음 조건을 갖추어야 한다.

```
- 여러 번 반복 실행할 수 있어야 한다.
- 리전, 출력 파일명, 조회 조건 등을 실행 시점에 바꿀 수 있어야 한다.
- AWS API 응답에서 필요한 정보만 보기 좋게 추출할 수 있어야 한다.
- 오류가 발생해도 원인을 확인할 수 있어야 한다.
- 결과를 화면에 출력하거나 파일로 저장할 수 있어야 한다.
- 다른 자동화 코드에서 재사용하기 쉽게 함수 단위로 분리되어야 한다.
```

이 장에서는 단순한 boto3 예제 코드를 점진적으로 개선하여 **운영 자동화 스크립트 형태**로 만들어본다.

# 4.3 자동화 스크립트의 기본 구조

## 4.3.1 가장 단순한 EC2 조회 코드

먼저 EC2 인스턴스 목록을 조회하는 가장 단순한 코드를 작성한다.

파일명은 `ec2_basic.py`로 작성한다.

```
import boto3

ec2 = boto3.client("ec2", region_name="ap-northeast-2")

response = ec2.describe_instances()

for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print(instance["InstanceId"], instance["State"]["Name"])
```

실행한다.

```
python ec2_basic.py
```

예상 출력 예시는 다음과 같다.

```
i-0123456789abcdef0 running
i-0abcdef1234567890 stopped
```

이 코드는 EC2 목록을 조회할 수 있다.

---

## 4.3.2 이 코드의 문제점

위 코드는 실무 자동화용으로는 다음 문제가 있다.

```
1. 리전이 코드에 고정되어 있다.
2. API 호출 코드와 출력 코드가 섞여 있다.
3. 예외 처리가 없다.
4. 필요한 정보만 구조화해서 저장하지 않는다.
5. 결과를 파일로 저장하지 않는다.
6. 실행할 때 조건을 바꿀 수 없다.
7. 다른 코드에서 재사용하기 어렵다.
```

예를 들어 서울 리전이 아니라 도쿄 리전을 조회하려면 코드를 직접 수정해야 한다.

```
ec2 = boto3.client("ec2", region_name="ap-northeast-2")
```

이 부분을 다음처럼 바꿔야 한다.

```
ec2 = boto3.client("ec2", region_name="ap-northeast-1")
```

운영 자동화에서는 실행할 때 옵션으로 리전을 지정하는 방식이 더 적절하다.

```
python ec2_inventory.py --region ap-northeast-2
```

또한 현재 코드는 API 호출 중 오류가 발생하면 그대로 프로그램이 종료된다.

권한 부족, 인증 정보 누락, 잘못된 리전, 네트워크 문제 등 다양한 상황을 고려하지 않았음.

따라서 이 장에서는 위 코드를 다음 형태로 개선한다.

```
단순 boto3 호출 코드
→ 함수화
→ 데이터 추출
→ 필터링
→ 예외 처리
→ 출력 정리
→ 파일 저장
→ 명령행 옵션 처리
→ 운영 자동화 스크립트 완성
```

# 4.4 main 함수와 실행 진입점 이해

## 4.4.1 main 함수가 필요한 이유

파이썬 스크립트가 짧을 때는 위에서 아래로 코드를 바로 작성해도 된다.

```
import boto3

ec2 = boto3.client("ec2")
response = ec2.describe_instances()
print(response)
```

하지만 코드가 길어지면 실행 흐름을 파악하기 어렵다.

그래서 일반적으로 실행 흐름을 `main()` 함수 안에 모은다.

```
def main():
    print("자동화 스크립트 시작")

main()
```

이 코드는 실행하면 다음처럼 출력된다.

```
자동화 스크립트 시작
```

하지만 보통은 다음 구조를 사용한다.

```
def main():
    print("자동화 스크립트 시작")

main()

if __name__=="__main__":
		main()
```

이 구조는 파이썬 자동화 스크립트에서 매우 자주 사용된다.

---

## 4.4.2 `if __name__ == "__main__"` 의미

파이썬 파일은 두 가지 방식으로 사용될 수 있다.

```
1. 직접 실행
2. 다른 파일에서 import
```

예를 들어 다음 파일이 있다고 하자.

파일명: `sample.py`

```
def hello():
    print("hello")

if __name__ == "__main__":
    hello()
```

직접 실행하면 `hello()`가 실행된다.

```
python sample.py
```

출력:

```
hello
```

하지만 다른 파일에서 import하면 자동으로 실행되지 않는다.

파일명: `test_import.py`

```
import sample

print("import 완료")
```

실행한다.

```
python test_import.py
```

출력:

```
import 완료
```

`hello()`는 자동으로 실행되지 않는다.

이 구조를 사용하는 이유는 다음과 같다.

```
- 현재 파일을 직접 실행할 때만 main()을 실행하기 위해서
- 나중에 다른 파이썬 파일에서 함수를 재사용할 수 있게 하기 위해서
- 자동화 스크립트의 실행 시작점을 명확하게 만들기 위해서
```

운영 자동화 스크립트에서는 다음 구조를 기본 형태로 사용한다.

```
def main():
    # 실행 흐름 작성
    pass

if __name__ == "__main__":
    main()
```

# 4.5 boto3 클라이언트 생성 코드 분리

## 4.5.1 기존 코드

boto3 클라이언트를 만들 때 다음처럼 작성했다.

```
import boto3

ec2 = boto3.client("ec2", region_name="ap-northeast-2")
```

이 코드는 EC2 서비스를 호출할 수 있는 클라이언트 객체를 생성한다.

```
boto3.client("ec2")
```

의미는 다음과 같다.

```
- boto3를 이용해 AWS 서비스 클라이언트를 생성한다.
- "ec2"는 사용할 AWS 서비스 이름이다.
- region_name은 API를 호출할 AWS 리전이다.
```

예를 들어 서울 리전 EC2를 조회하려면 다음처럼 작성한다.

```
boto3.client("ec2",region_name="ap-northeast-2")
```

도쿄 리전을 조회하려면 다음처럼 작성한다.

```
boto3.client("ec2",region_name="ap-northeast-1")
```

---

## 4.5.2 클라이언트 생성 함수를 만드는 이유

운영 자동화 코드에서는 boto3 클라이언트 생성 코드를 함수로 분리하는 것이 좋다.

```
def create_ec2_client(region):
    return boto3.client("ec2", region_name=region)
```

이렇게 만들면 다음 장점이 있다.

```
- 리전을 매개변수로 받을 수 있다.
- 클라이언트 생성 로직을 재사용할 수 있다.
- 나중에 profile_name, endpoint_url 같은 옵션을 추가하기 쉽다.
- main 함수의 흐름이 간결해진다.
```

전체 코드는 다음과 같다.

```
import boto3

def create_ec2_client(region):
    return boto3.client("ec2", region_name=region)

def main():
    region = "ap-northeast-2"
    ec2 = create_ec2_client(region)

    response = ec2.describe_instances()

    for reservation in response["Reservations"]:
        for instance in reservation["Instances"]:
            print(instance["InstanceId"], instance["State"]["Name"])

if __name__ == "__main__":
    main()
```

파일명은 `ec2_step1_client.py`로 저장한다.

```
python ec2_step1_client.py
```

---

## 4.5.3 함수 매개변수 이해

다음 함수에서 `region`은 매개변수다.

```
def create_ec2_client(region):
    return boto3.client("ec2", region_name=region)
```

실행할 때 다음처럼 값을 전달한다.

```
ec2=create_ec2_client("ap-northeast-2")
```

그러면 함수 내부에서는 다음처럼 동작한다.

```
region = "ap-northeast-2"
boto3.client("ec2", region_name="ap-northeast-2")
```

즉, 함수는 고정된 코드가 아니라 값을 받아서 동작을 바꿀 수 있는 코드 블록이다.

# 4.6 AWS API 응답 구조 다루기

## 4.6.1 describe\_instances 응답 구조

EC2 인스턴스를 조회할 때 사용하는 API는 다음과 같다.

```
ec2.describe_instances()
```

이 API는 딕셔너리 형태의 응답을 반환한다.

응답 구조는 단순하지 않고, 리스트와 딕셔너리가 중첩되어 있다.

대략적인 구조는 다음과 같다.

```
response
└── Reservations
    └── [
        {
          "ReservationId": "...",
          "Instances": [
              {
                "InstanceId": "i-0123456789abcdef0",
                "InstanceType": "t3.micro",
                "State": {
                    "Name": "running"
                },
                "PrivateIpAddress": "10.0.1.10",
                "PublicIpAddress": "3.35.10.20",
                "Tags": [
                    {
                      "Key": "Name",
                      "Value": "web-server"
                    }
                ]
              }
          ]
        }
    ]
```

여기서 실제 인스턴스 정보는 다음 위치에 있다.

```
response["Reservations"][0]["Instances"][0]
```

하지만 인스턴스가 여러 개일 수 있으므로 반복문을 사용해야 한다.

```
for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print(instance["InstanceId"])
```

---

## 4.6.2 중첩 반복문 이해

다음 코드를 다시 보자.

```
for reservation in response["Reservations"]:
    for instance in reservation["Instances"]:
        print(instance["InstanceId"])
```

첫 번째 반복문은 `Reservations` 목록을 순회한다.

```
for reservation in response["Reservations"]:
```

두 번째 반복문은 각 reservation 안의 `Instances` 목록을 순회한다.

```
for instance in reservation["Instances"]:
```

이 구조가 필요한 이유는 AWS EC2의 응답 구조가 다음처럼 되어 있기 때문이다.

```
Reservations는 리스트
각 Reservation 안에 Instances 리스트가 있음
각 Instance 안에 InstanceId, State, InstanceType 같은 정보가 있음
```

따라서 EC2 목록 조회 코드는 보통 중첩 반복문을 사용한다.

---

## 4.6.3 응답 구조를 확인하는 방법

API 응답 구조가 헷갈릴 때는 전체 응답을 출력해보는 것이 좋다.

```
import boto3
import json

ec2 = boto3.client("ec2", region_name="ap-northeast-2")

response = ec2.describe_instances()

print(json.dumps(response, indent=2, default=str))
```

여기서 `json.dumps()`는 파이썬 데이터를 JSON 문자열로 변환한다.

```
json.dumps(response,indent=2,default=str)
```

옵션의 의미는 다음과 같다.

```
response
- 출력할 파이썬 딕셔너리 데이터

indent=2
- 들여쓰기를 적용해서 보기 좋게 출력

default=str
- datetime 같은 JSON으로 바로 변환되지 않는 값을 문자열로 변환
```

AWS 응답에는 날짜 데이터가 포함되는 경우가 많다.

날짜 데이터는 그대로 JSON으로 변환되지 않을 수 있으므로 `default=str`을 사용한다.

# 4.7 필요한 데이터만 추출하기

## 4.7.1 원본 응답을 그대로 사용하지 않는 이유

AWS API 응답에는 많은 정보가 들어 있다.

하지만 운영자가 매번 모든 정보를 확인할 필요는 없다.

EC2 인스턴스 목록 점검에서는 보통 다음 정보 정도를 우선 확인한다.

```
- 인스턴스 ID
- 인스턴스 타입
- 상태
- 프라이빗 IP
- 퍼블릭 IP
- Name 태그
```

따라서 원본 응답에서 필요한 값만 추출하여 새로운 딕셔너리로 정리하는 것이 좋다.

---

## 4.7.2 인스턴스 정보 추출 함수 작성

다음 함수를 작성한다.

```
def extract_instance_info(reservations):
    instance_list = []

    for reservation in reservations:
        for instance in reservation["Instances"]:
            instance_info = {
                "InstanceId": instance.get("InstanceId"),
                "InstanceType": instance.get("InstanceType"),
                "State": instance.get("State", {}).get("Name"),
                "PrivateIpAddress": instance.get("PrivateIpAddress", "-"),
                "PublicIpAddress": instance.get("PublicIpAddress", "-"),
            }

            instance_list.append(instance_info)

    return instance_list
```

이 함수의 역할은 다음과 같다.

```
입력:
- describe_instances() 응답의 Reservations 목록

처리:
- 각 EC2 인스턴스에서 필요한 정보만 추출
- 새 딕셔너리로 정리
- 리스트에 추가

출력:
- 인스턴스 정보 딕셔너리 리스트
```

출력 데이터 예시는 다음과 같다.

```
[
    {
        "InstanceId": "i-0123456789abcdef0",
        "InstanceType": "t3.micro",
        "State": "running",
        "PrivateIpAddress": "10.0.1.10",
        "PublicIpAddress": "3.35.10.20"
    },
    {
        "InstanceId": "i-0abcdef1234567890",
        "InstanceType": "t3.micro",
        "State": "stopped",
        "PrivateIpAddress": "10.0.1.20",
        "PublicIpAddress": "-"
    }
]
```

---

## 4.7.3 `get()` 메서드 사용 이유

다음 코드를 보자.

```
instance.get("PublicIpAddress","-")
```

딕셔너리에서 값을 가져올 때는 보통 다음처럼 작성할 수도 있다.

```
instance["PublicIpAddress"]
```

하지만 이 방식은 해당 키가 없으면 오류가 발생한다.

```
KeyError: 'PublicIpAddress'
```

EC2 인스턴스는 퍼블릭 IP가 없을 수 있다.

예를 들어 프라이빗 서브넷에 있는 인스턴스는 `PublicIpAddress` 키 자체가 없을 수 있음.

따라서 안전하게 값을 꺼내려면 `get()`을 사용한다.

```
instance.get("PublicIpAddress","-")
```

의미는 다음과 같다.

```
- PublicIpAddress 키가 있으면 해당 값을 반환
- 없으면 "-" 반환
```

---

## 4.7.4 중첩 딕셔너리에서 값 가져오기

인스턴스 상태는 다음 구조로 들어 있다.

```
"State": {
    "Code": 16,
    "Name": "running"
}
```

상태 이름만 가져오려면 다음처럼 작성한다.

```
instance["State"]["Name"]
```

하지만 안전하게 작성하려면 다음처럼 작성한다.

```
instance.get("State", {}).get("Name")
```

이 코드의 의미는 다음과 같다.

```
1. instance에서 State 값을 가져온다.
2. State 키가 없으면 빈 딕셔너리 {}를 사용한다.
3. 그 결과에서 Name 값을 가져온다.
```

즉, `State` 키가 없더라도 프로그램이 바로 종료되지 않게 만든다.

---

## 4.7.5 Name 태그 추출하기

EC2 인스턴스 이름은 보통 `Name` 태그에 저장된다.

태그 구조는 다음과 같다.

```
"Tags": [
    {
        "Key": "Name",
        "Value": "web-server"
    },
    {
        "Key": "Env",
        "Value": "dev"
    }
]
```

`Name` 태그만 추출하는 함수를 작성한다.

```
def get_name_tag(instance):
    tags = instance.get("Tags", [])

    for tag in tags:
        if tag.get("Key") == "Name":
            return tag.get("Value")

    return "-"
```

이 함수는 다음 순서로 동작한다.

```
1. instance에서 Tags 값을 가져온다.
2. Tags가 없으면 빈 리스트를 사용한다.
3. 태그 목록을 반복한다.
4. Key 값이 Name인 태그를 찾는다.
5. 찾으면 Value 값을 반환한다.
6. 끝까지 못 찾으면 "-"를 반환한다.
```

이제 인스턴스 정보 추출 함수에 Name 태그도 포함한다.

```
def extract_instance_info(reservations):
    instance_list = []

    for reservation in reservations:
        for instance in reservation["Instances"]:
            instance_info = {
                "Name": get_name_tag(instance),
                "InstanceId": instance.get("InstanceId"),
                "InstanceType": instance.get("InstanceType"),
                "State": instance.get("State", {}).get("Name"),
                "PrivateIpAddress": instance.get("PrivateIpAddress", "-"),
                "PublicIpAddress": instance.get("PublicIpAddress", "-"),
            }

            instance_list.append(instance_info)

    return instance_list
```

# 4.8 반복 조회와 필터링

## 4.8.1 필터링이 필요한 이유

운영 자동화에서는 전체 리소스를 조회한 뒤 필요한 조건만 골라내는 경우가 많다.

예를 들어 다음과 같은 요구사항이 있을 수 있다.

```
- running 상태의 EC2만 출력
- stopped 상태의 EC2만 출력
- 특정 태그가 붙은 인스턴스만 출력
- 퍼블릭 IP를 가진 인스턴스만 출력
- 특정 인스턴스 타입만 출력
```

이런 작업을 필터링이라고 한다.

---

## 4.8.2 상태 기준 필터링

인스턴스 목록에서 특정 상태만 남기는 함수를 작성한다.

```
def filter_instances_by_state(instances, state):
    if state == "all":
        return instances

    filtered_instances = []

    for instance in instances:
        if instance["State"] == state:
            filtered_instances.append(instance)

    return filtered_instances
```

이 함수의 동작은 다음과 같다.

```
- state 값이 "all"이면 전체 목록 반환
- 그렇지 않으면 인스턴스 상태를 비교
- 일치하는 인스턴스만 새 리스트에 추가
- 필터링된 리스트 반환
```

예를 들어 다음 데이터가 있다고 하자.

```
instances= [
    {"InstanceId":"i-001","State":"running"},
    {"InstanceId":"i-002","State":"stopped"},
    {"InstanceId":"i-003","State":"running"},
]
```

다음처럼 호출하면,

```
running_instances = filter_instances_by_state(instances, "running")
```

결과는 다음과 같다.

```
[
    {"InstanceId":"i-001","State":"running"},
    {"InstanceId":"i-003","State":"running"},
]
```

---

## 4.8.3 리스트 컴프리헨션 방식

위 코드는 리스트 컴프리헨션으로 더 짧게 작성할 수 있다.

```
def filter_instances_by_state(instances, state):
    if state == "all":
        return instances

    return [
        instance
        for instance in instances
        if instance["State"] == state
    ]
```

리스트 컴프리헨션은 다음 구조를 가진다.

```
[ 표현식 for 변수 in 반복대상 if 조건 ]
```

예를 들어 다음 코드는,

```
[
    instance
    for instance in instances
    if instance["State"] == state
]
```

다음 반복문과 같은 의미다.

```
filtered_instances = []

for instance in instances:
    if instance["State"] == state:
        filtered_instances.append(instance)
```

초보자에게는 일반 `for`문 방식이 이해하기 쉽고,

익숙해지면 리스트 컴프리헨션 방식도 사용할 수 있다.

---

## 4.8.4 퍼블릭 IP 보유 인스턴스 필터링

퍼블릭 IP를 가진 인스턴스만 찾는 함수도 작성해볼 수 있다.

```
def filter_instances_with_public_ip(instances):
    filtered_instances = []

    for instance in instances:
        if instance["PublicIpAddress"] != "-":
            filtered_instances.append(instance)

    return filtered_instances
```

리스트 컴프리헨션 방식은 다음과 같다.

```
def filter_instances_with_public_ip(instances):
    return [
        instance
        for instance in instances
        if instance["PublicIpAddress"] != "-"
    ]
```

이런 필터링은 보안 점검에서 자주 사용된다.

예를 들어 퍼블릭 IP를 가진 인스턴스 목록을 뽑아 외부 노출 여부를 점검할 수 있다.

# 4.9 예외 처리 적용

## 4.9.1 예외 처리가 필요한 이유

자동화 스크립트는 항상 정상 상황에서만 실행되지 않는다.

AWS API 호출 중 다음 문제가 발생할 수 있다.

```
- AWS 자격 증명이 설정되어 있지 않음
- IAM 권한이 부족함
- 잘못된 리전명을 사용함
- 네트워크 연결이 불안정함
- API 호출 제한이 발생함
- 존재하지 않는 리소스를 조회함
```

예외 처리를 하지 않으면 오류 발생 시 프로그램이 바로 종료된다.

운영 자동화에서는 오류를 사용자에게 명확히 알려주고, 필요한 경우 다음 작업으로 넘어갈 수 있어야 한다.

---

## 4.9.2 try except 기본 구조

파이썬의 예외 처리는 `try except` 구조를 사용한다.

```
try:
    # 오류가 발생할 수 있는 코드
    pass
except:
    # 오류가 발생했을 때 실행할 코드
    pass
```

예를 들어 다음 코드는 0으로 나누기 오류가 발생한다.

```
number=10/0
```

실행하면 다음 오류가 발생한다.

```
ZeroDivisionError: division by zero
```

예외 처리를 적용하면 다음처럼 작성할 수 있다.

```
try:
    number = 10 / 0
except ZeroDivisionError:
    print("0으로 나눌 수 없음")
```

출력:

```
0으로 나눌 수 없음
```

---

## 4.9.3 boto3 예외 처리

boto3 관련 예외 처리를 위해 다음 모듈을 가져온다.

```
from botocore.exceptions import ClientError, NoCredentialsError
```

대표적인 예외는 다음과 같다.

```
ClientError
- AWS API 호출 중 발생하는 일반적인 오류
- 권한 부족, 잘못된 요청, 리소스 없음 등의 상황에서 발생

NoCredentialsError
- AWS 자격 증명을 찾을 수 없을 때 발생
```

EC2 조회 함수에 예외 처리를 추가한다.

```
from botocore.exceptions import ClientError, NoCredentialsError

def get_instances(ec2):
    try:
        response = ec2.describe_instances()
        return response["Reservations"]

    except NoCredentialsError:
        print("[오류] AWS 자격 증명을 찾을 수 없음")
        return []

    except ClientError as error:
        print("[오류] AWS API 호출 중 문제가 발생함")
        print(error)
        return []
```

이 함수는 오류가 발생하면 빈 리스트를 반환한다.

```
return []
```

빈 리스트를 반환하는 이유는 이후 코드가 반복문을 실행하더라도 오류 없이 끝나게 하기 위해서다.

```
for reservation in reservations:
    ...
```

`reservations`가 빈 리스트이면 반복문은 아무 작업도 하지 않고 종료된다.

---

## 4.9.4 ClientError에서 오류 코드 확인하기

`ClientError`는 내부에 AWS 오류 정보를 가지고 있다.

오류 코드는 다음처럼 확인할 수 있다.

```
error.response["Error"]["Code"]
```

오류 메시지는 다음처럼 확인할 수 있다.

```
error.response["Error"]["Message"]
```

조금 더 정리된 예외 처리는 다음과 같다.

```
def get_instances(ec2):
    try:
        response = ec2.describe_instances()
        return response["Reservations"]

    except NoCredentialsError:
        print("[오류] AWS 자격 증명을 찾을 수 없음")
        return []

    except ClientError as error:
        error_code = error.response["Error"]["Code"]
        error_message = error.response["Error"]["Message"]

        print(f"[오류] AWS API 호출 실패: {error_code}")
        print(f"[메시지] {error_message}")

        return []
```

예를 들어 권한이 부족하면 다음과 비슷한 메시지가 출력될 수 있다.

```
[오류] AWS API 호출 실패: UnauthorizedOperation
[메시지] You are not authorized to perform this operation.
```

이런 방식은 운영자가 원인을 파악하는 데 도움이 된다.

# 4.10 출력 형식 정리

## 4.10.1 단순 출력의 한계

처음에는 다음처럼 출력할 수 있다.

```
print(instance)
```

하지만 딕셔너리 전체를 출력하면 보기 어렵다.

{'Name': 'web-server', 'InstanceId': 'i-0123456789abcdef0', 'InstanceType': 't3.micro', 'State': 'running', 'PrivateIpAddress': '10.0.1.10', 'PublicIpAddress': '3.35.10.20'}

## 4.10.2 f-string 정렬

파이썬의 f-string을 사용하면 출력 폭과 정렬 방식을 지정할 수 있다.

```
name="web-server"
print(f"{name:<20}")
```

여기서 `<20`의 의미는 다음과 같다.

```
<  : 왼쪽 정렬
20 : 전체 출력 폭을 20칸으로 설정
```

오른쪽 정렬은 `>`를 사용한다.

```
print(f"{name:>20}")
```

가운데 정렬은 `^`를 사용한다.

```
print(f"{name:^20}")
```

자동화 출력에서는 보통 왼쪽 정렬을 많이 사용한다.

## 4.10.3 EC2 목록 표 출력 함수

다음 함수를 작성한다.

```
def print_instance_table(instances):

        f"{'InstanceId':<22} "
        f"{'Type':<12} "
        f"{'State':<12} "
        f"{'PrivateIP':<15} "

    print("-" * 100)

            f"{instance['State']:<12} "
            f"{instance['PrivateIpAddress']:<15} "
            f"{instance['PublicIpAddress']:<15}"
        )
```

이 함수는 인스턴스 목록을 표 형태로 출력한다.

## 4.10.4 데이터가 없을 때 처리

조회 결과가 없을 때는 아무것도 출력하지 않는 것보다 메시지를 보여주는 것이 좋다.

def print_instance_table(instances):

```

return

import csv
```

딕셔너리 리스트를 CSV로 저장할 때는 `csv.DictWriter`가 편리하다.

```
writer = csv.DictWriter(file,fieldnames=fieldnames)
```

`DictWriter`는 딕셔너리의 키를 컬럼 이름으로 사용한다.

---

## 4.12.3 CSV 저장 함수

다음 함수를 작성한다.

```
import csv

def save_to_csv(data, filename):
    if not data:
        print("저장할 데이터가 없음")
        return

    fieldnames = data[0].keys()

    with open(filename, "w", newline="", encoding="utf-8-sig") as file:
        writer = csv.DictWriter(file, fieldnames=fieldnames)

        writer.writeheader()
        writer.writerows(data)

    print(f"CSV 파일 저장 완료: {filename}")
```

각 코드의 의미를 확인한다.

```
if not data:
    print("저장할 데이터가 없음")
    return
```

저장할 데이터가 없으면 CSV 파일을 만들지 않고 함수를 종료한다.

```
fieldnames = data[0].keys()
```

첫 번째 딕셔너리의 키를 CSV 컬럼명으로 사용한다.

예를 들어 데이터가 다음과 같다면,

```
{
	"Name":"web-server",
	"InstanceId":"i-0123456789abcdef0",
	"State":"running"
}
```

컬럼명은 다음과 같다.

```
Name, InstanceId, State
```

다음 코드는 파일을 쓰기 모드로 연다.

```
with open(filename,"w",newline="",encoding="utf-8-sig") as file:
```

여기서 `newline=""`을 사용하는 이유는 CSV 저장 시 빈 줄이 추가되는 문제를 방지하기 위해서다.

`encoding="utf-8-sig"`는 엑셀에서 한글이 깨지지 않도록 하기 위해 사용한다.

다음 코드는 헤더를 작성한다.

```
writer.writeheader()
```

다음 코드는 실제 데이터를 여러 줄로 작성한다.

```
writer.writerows(data)
```

# 4.14 EC2 인벤토리 자동화 스크립트 완성

이제 지금까지 학습한 내용을 모두 합쳐 EC2 인벤토리 자동화 스크립트를 완성한다.

## 4.14.1 최종 요구사항

스크립트 요구사항은 다음과 같다.

```
- EC2 인스턴스 목록을 조회한다.
- Name, InstanceId, InstanceType, State, PrivateIpAddress, PublicIpAddress를 출력한다.
- --region 옵션으로 조회 리전을 지정할 수 있다.
- --state 옵션으로 all, running, stopped, terminated 중 하나를 선택할 수 있다.
- 결과를 표 형태로 출력한다.
- 결과를 CSV 파일로 저장한다.
- AWS API 호출 오류를 처리한다.
```

---

## 4.14.2 최종 코드

파일명: `ec2_inventory.py`

```
import argparse
import csv
import boto3
from botocore.exceptions import ClientError, NoCredentialsError

def parse_args():
    parser = argparse.ArgumentParser(
        description="EC2 인스턴스 목록 조회 자동화 스크립트"
    )

    parser.add_argument(
        "--region",
        default="ap-northeast-2",
        help="조회할 AWS 리전"
    )

    parser.add_argument(
        "--state",
        default="all",
        choices=["all", "running", "stopped", "terminated"],
        help="조회할 인스턴스 상태"
    )

    parser.add_argument(
        "--output",
        default="ec2-instances.csv",
        help="CSV 출력 파일명"
    )

    return parser.parse_args()

def create_ec2_client(region):
    return boto3.client("ec2", region_name=region)

def get_instances(ec2):
    try:
        response = ec2.describe_instances()
        return response["Reservations"]

    except NoCredentialsError:
        print("[오류] AWS 자격 증명을 찾을 수 없음")
        return []

    except ClientError as error:
        error_code = error.response["Error"]["Code"]
        error_message = error.response["Error"]["Message"]

        print(f"[오류] AWS API 호출 실패: {error_code}")
        print(f"[메시지] {error_message}")

        return []

def get_name_tag(instance):
    tags = instance.get("Tags", [])

    for tag in tags:
        if tag.get("Key") == "Name":
            return tag.get("Value")

    return "-"

def extract_instance_info(reservations):
    instance_list = []

    for reservation in reservations:
        for instance in reservation["Instances"]:
            instance_info = {
                "Name": get_name_tag(instance),
                "InstanceId": instance.get("InstanceId"),
                "InstanceType": instance.get("InstanceType"),
                "State": instance.get("State", {}).get("Name"),
                "PrivateIpAddress": instance.get("PrivateIpAddress", "-"),
                "PublicIpAddress": instance.get("PublicIpAddress", "-"),
            }

            instance_list.append(instance_info)

    return instance_list

def filter_instances_by_state(instances, state):
    if state == "all":
        return instances

    return [
        instance
        for instance in instances
        if instance["State"] == state
    ]

def print_instance_table(instances):
    if not instances:
        print("조회된 인스턴스가 없음")
        return

    print(
        f"{'Name':<20} "
        f"{'InstanceId':<22} "
        f"{'Type':<12} "
        f"{'State':<12} "
        f"{'PrivateIP':<15} "
        f"{'PublicIP':<15}"
    )
    print("-" * 100)

    for instance in instances:
        print(
            f"{instance['Name']:<20} "
            f"{instance['InstanceId']:<22} "
            f"{instance['InstanceType']:<12} "
            f"{instance['State']:<12} "
            f"{instance['PrivateIpAddress']:<15} "
            f"{instance['PublicIpAddress']:<15}"
        )

def save_to_csv(data, filename):
    if not data:
        print("저장할 데이터가 없음")
        return

    fieldnames = data[0].keys()

    with open(filename, "w", newline="", encoding="utf-8-sig") as file:
        writer = csv.DictWriter(file, fieldnames=fieldnames)

        writer.writeheader()
        writer.writerows(data)

    print(f"CSV 파일 저장 완료: {filename}")

def main():
    args = parse_args()

    ec2 = create_ec2_client(args.region)

    reservations = get_instances(ec2)
    instances = extract_instance_info(reservations)
    filtered_instances = filter_instances_by_state(instances, args.state)

    print_instance_table(filtered_instances)
    save_to_csv(filtered_instances, args.output)

if __name__ == "__main__":
    main()
```

7. save_to_csv()
   - CSV 파일로 저장

→ 파일 저장

확인 명령:

```
aws configure list
```

해결 방법:

```
aws configure
```

또는 환경 변수를 사용하는 경우 다음 값을 확인한다.

```
echo$AWS_ACCESS_KEY_ID
echo$AWS_SECRET_ACCESS_KEY
```

Windows PowerShell:

```
echo$env:AWS_ACCESS_KEY_ID
echo$env:AWS_SECRET_ACCESS_KEY
```

## 4.17.2 UnauthorizedOperation

오류 예시:

```
An error occurred (UnauthorizedOperation) when calling the DescribeInstances operation
```

원인:

```
현재 IAM 사용자 또는 역할에 EC2 조회 권한이 없음
```

필요 권한 예시:

```
ec2:DescribeInstances
```

실습 환경에서는 읽기 전용 권한을 부여하는 것이 좋다.

예:

```
AmazonEC2ReadOnlyAccess
```

## 4.17.3 AccessDenied

오류 예시:

```
An error occurred (AccessDenied) when calling the ListBuckets operation
```

원인:

```
S3 목록 조회 권한이 없음
```

필요 권한 예시:

```
s3:ListAllMyBuckets
```

실습용 관리형 정책 예:

```
AmazonS3ReadOnlyAccess
```

## 4.17.4 잘못된 리전명

오류 예시:

```
Could not connect to the endpoint URL
```

원인 예시:

```
리전명을 잘못 입력했음
ap-northeast-2가 아니라 ap-northeast2처럼 입력했음
```

올바른 서울 리전명:

```
ap-northeast-2
```

도쿄 리전명:

```
ap-northeast-1
```

## 4.17.5 CSV 파일 한글 깨짐

엑셀에서 CSV 파일을 열었을 때 한글이 깨질 수 있다.

이 경우 파일 저장 시 다음 인코딩을 사용한다.

```
encoding="utf-8-sig"
```

예:

```
with open(filename, "w", newline="", encoding="utf-8-sig") as file:
    writer = csv.DictWriter(file, fieldnames=fieldnames)
```

# 4.18 정리

```
1. 자동화 스크립트는 main 함수 중심으로 구성하면 실행 흐름이 명확해진다.

2. boto3 클라이언트 생성, API 호출, 데이터 추출, 출력, 저장 기능은 함수로 분리하는 것이 좋다.

3. AWS API 응답은 중첩된 딕셔너리와 리스트 구조가 많으므로 필요한 데이터만 추출해야 한다.

4. get() 메서드를 사용하면 없는 키에 대한 오류를 줄일 수 있다.

5. 운영 자동화에서는 필터링 기능이 중요하다.

6. try except를 사용해 AWS API 호출 오류를 처리해야 한다.

7. 결과는 화면 출력뿐 아니라 CSV 또는 JSON 파일로 저장할 수 있어야 한다.

8. argparse를 사용하면 리전, 상태, 출력 파일명 같은 옵션을 실행 시점에 지정할 수 있다.

9. EC2 인벤토리 스크립트 구조는 S3, IAM, 보안 그룹, CloudWatch 등 다른 AWS 서비스 자동화에도 재사용할 수 있다.
```
