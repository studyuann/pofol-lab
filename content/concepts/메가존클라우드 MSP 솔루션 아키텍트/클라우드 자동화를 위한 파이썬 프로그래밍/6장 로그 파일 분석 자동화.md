# 6장. 로그 파일 분석 자동화

---

## 장 개요

이 장에서는 시스템과 애플리케이션에서 생성되는 로그 파일을 Python으로 읽고 분석하는 방법을 학습한다.

로그는 운영 환경에서 문제 원인을 찾거나, 서비스 상태를 확인하거나, 반복적으로 발생하는 오류를 추적할 때 매우 중요한 자료이다. 하지만 로그 파일은 시간이 지날수록 매우 커지고, 사람이 직접 눈으로 확인하기에는 한계가 있다.

이 장에서는 텍스트 로그와 JSON 로그의 기본 구조를 이해하고, Python을 이용해 로그 파일을 줄 단위로 읽는 방법을 학습한다. 이후 특정 문자열 검색, 조건 필터링, 정규표현식을 이용한 값 추출, 상태코드 집계, IP별 요청 수 집계, URL별 요청 수 집계, 시간대별 집계까지 단계적으로 실습한다.

마지막에는 `argparse`, 함수 분리, 예외 처리를 포함한 자동화 스타일의 로그 분석 스크립트를 작성한다.

이 장의 목표는 단순히 로그 파일을 읽는 것이 아니라, **운영자가 반복적으로 수행하는 로그 확인 작업을 Python 코드로 자동화하는 기본 흐름을 익히는 것**이다.

# 6.1 로그 자동화가 필요한 이유

## 1. 로그란 무엇인가

로그는 시스템, 서버, 애플리케이션, 네트워크 장비 등이 동작하면서 남기는 기록이다.

예를 들어 웹 서버는 사용자가 어떤 URL에 접속했는지, 응답 상태코드는 무엇이었는지, 요청 시간이 언제였는지 등을 로그로 남긴다.

애플리케이션은 서비스 시작, 오류 발생, 데이터베이스 연결 실패, 외부 API 호출 실패 같은 정보를 로그로 남길 수 있다.

대표적으로 로그에는 다음과 같은 정보가 포함된다.

* 요청 시간

* 요청한 클라이언트 IP

* 요청 URL

* HTTP 메서드

* 응답 상태코드

* 에러 메시지

* 사용자 ID

* 처리 시간

* 서버 이름

* 프로세스 정보

운영 환경에서는 장애가 발생했을 때 가장 먼저 로그를 확인하는 경우가 많다.

예를 들어 웹 서비스에서 사용자가 “페이지가 열리지 않는다”고 신고하면 운영자는 다음과 같은 항목을 확인한다.

* 해당 시간대에 500 오류가 발생했는가

* 특정 API에서 오류가 반복되는가

* 특정 IP에서 비정상적으로 많은 요청이 들어왔는가

* 데이터베이스 연결 실패 로그가 있었는가

* 인증 실패나 권한 오류가 증가했는가

즉, 로그는 운영 상태를 확인하기 위한 가장 기본적인 데이터이다.

---

## 2. 수동 로그 확인의 한계

로그 파일이 작을 때는 사람이 직접 열어서 확인할 수 있다.

예를 들어 로그가 10줄, 20줄 정도라면 눈으로 `ERROR` 문구를 찾는 것이 어렵지 않다.

하지만 실제 운영 환경에서는 로그가 매우 많다.

웹 서버의 경우 하루에도 수천 줄, 수만 줄, 수백만 줄의 로그가 쌓일 수 있다. 이런 로그를 사람이 직접 확인하는 것은 비효율적이고 실수도 많이 발생한다.

운영자가 자주 수행하는 작업은 다음과 같다.

* `ERROR`가 포함된 줄만 찾기

* `WARN` 로그만 찾기

* HTTP 상태코드가 `500`인 요청만 찾기

* `4xx`, `5xx` 상태코드 개수 세기

* 특정 IP가 몇 번 요청했는지 확인하기

* 특정 URL이 얼마나 호출되었는지 확인하기

* 특정 시간대에 요청이 몰렸는지 확인하기

* 잘못된 JSON 로그 줄 찾기

* 오류 로그만 별도 파일로 저장하기

이런 작업은 반복적이고 규칙적이다.

반복적이고 규칙적인 작업은 Python 자동화에 적합하다.

---

## 3. 로그 분석 자동화의 실무 흐름

운영자가 로그를 분석할 때는 보통 다음 순서로 접근한다.

1. 문제가 발생한 시간대를 확인한다.

2. 해당 시간대의 로그 파일을 찾는다.

3. `ERROR`, `WARN`, `Exception`, `timeout` 같은 키워드를 검색한다.

4. 웹 서버 로그라면 `4xx`, `5xx` 상태코드를 확인한다.

5. 같은 에러 메시지가 반복되는지 확인한다.

6. 특정 IP, URL, 사용자, 상태코드에 요청이 집중되는지 확인한다.

7. 분석 결과를 정리해 장애 원인 분석이나 보고에 활용한다.

Python 로그 자동화는 이 과정에서 반복되는 검색, 필터링, 집계 작업을 코드로 대신 수행하는 것이다.

---

## 4. 로그 자동화의 기본 흐름

Python을 이용한 로그 자동화는 보통 다음 흐름으로 작성한다.

```
로그 파일 열기
↓
한 줄씩 읽기
↓
필요한 문자열 또는 패턴 찾기
↓
조건에 맞는 로그만 필터링
↓
필요한 값 추출
↓
개수 집계
↓
결과 출력 또는 파일 저장
```

코드 흐름으로 보면 다음과 같다.

```
with open("app.log","r",encoding="utf-8") as file:
	for line in file:
		if "ERROR" in line:
	  print(line.strip())
```

이 코드는 가장 기본적인 로그 자동화 구조이다.

* `open()`으로 로그 파일을 연다.

* `for line in file:`로 한 줄씩 읽는다.

* `if "ERROR" in line:`로 조건을 검사한다.

* `print()`로 조건에 맞는 로그만 출력한다.

이 장에서는 이 기본 구조를 점진적으로 확장한다.

# 6.2 로그 형식 이해

## 1. 텍스트 로그

텍스트 로그는 사람이 읽기 쉬운 문자열 형태의 로그이다.

예를 들면 다음과 같다.

```
2026-04-20 10:01:11 INFO service started
2026-04-20 10:01:15 ERROR database connection failed
2026-04-20 10:01:20 INFO retry started
2026-04-20 10:01:25 ERROR timeout occurred
```

이 로그는 다음 요소로 구성되어 있다.

```
날짜 시간 로그레벨 메시지
```

예를 들어 아래 한 줄을 보자.

```
2026-04-20 10:01:15 ERROR database connection failed
```

각 항목은 다음 의미를 가진다.

| 항목 | 값 | 의미 |
| --- | --- | --- |
| 날짜 | `2026-04-20` | 로그가 발생한 날짜 |
| 시간 | `10:01:15` | 로그가 발생한 시각 |
| 로그 레벨 | `ERROR` | 오류 로그 |
| 메시지 | `database connection failed` | 데이터베이스 연결 실패 |

텍스트 로그는 사람이 읽기 쉽지만, 프로그램이 구조적으로 처리하려면 문자열 자르기, 정규표현식, 조건문 등이 필요하다.

---

## 2. JSON 로그

JSON 로그는 한 줄이 JSON 형식으로 저장된 로그이다.

예를 들면 다음과 같다.

```
{"time":"2026-04-20T10:01:11","level":"INFO","message":"service started"}
{"time":"2026-04-20T10:01:15","level":"ERROR","message":"database connection failed"}
{"time":"2026-04-20T10:01:20","level":"INFO","message":"retry started"}
```

JSON 로그는 다음처럼 키와 값으로 구성된다.

```
{
  "time":"2026-04-20T10:01:15",
  "level":"ERROR",
  "message":"database connection failed"
}
```

JSON 로그의 장점은 프로그램이 구조적으로 다루기 쉽다는 점이다.

예를 들어 `level` 값을 확인하고 싶으면 문자열에서 직접 찾지 않고 다음처럼 접근할 수 있다.

```
log["level"]
```

또는 더 안전하게 다음처럼 접근할 수도 있다.

```
log.get("level")
```

텍스트 로그는 사람이 보기 쉽고, JSON 로그는 프로그램이 분석하기 좋다.

---

## 3. 액세스 로그와 에러 로그

운영 환경에서 자주 보는 로그는 크게 액세스 로그와 에러 로그로 나눌 수 있다.

### 액세스 로그

액세스 로그는 사용자의 요청과 서버의 응답 정보를 기록한다.

예를 들면 다음과 같다.

```
127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 200 1234
```

이 로그에는 다음 정보가 들어 있다.

| 항목 | 예시 | 의미 |
| --- | --- | --- |
| IP 주소 | `127.0.0.1` | 요청한 클라이언트 IP |
| 시간 | `[20/Apr/2026:10:01:15 +0900]` | 요청 발생 시간 |
| 메서드 | `GET` | HTTP 요청 메서드 |
| 경로 | `/api/items` | 요청 URL 경로 |
| 프로토콜 | `HTTP/1.1` | HTTP 버전 |
| 상태코드 | `200` | 응답 상태코드 |
| 응답 크기 | `1234` | 응답 바이트 크기 |

액세스 로그는 다음을 분석할 때 유용하다.

* 특정 URL 호출 횟수

* 특정 IP 요청 횟수

* 404 오류 발생 횟수

* 500 오류 발생 횟수

* 로그인 실패 요청

* 관리자 페이지 접근 시도

### 에러 로그

에러 로그는 오류, 경고, 예외 상황을 기록한다.

예를 들면 다음과 같다.

```
2026-04-20 10:01:15 ERROR database connection failed
2026-04-20 10:01:25 ERROR timeout occurred
2026-04-20 10:01:40 WARN retry count exceeded
```

에러 로그는 다음을 분석할 때 유용하다.

* 서비스 장애 원인

* 데이터베이스 연결 실패

* 외부 API 호출 실패

* 인증 오류

* 권한 오류

* 예외 발생 위치

이번 장에서는 텍스트 로그, 액세스 로그, JSON 로그를 모두 다룬다.

# 6.3 Python으로 로그 파일 읽기

## 1. 실습 파일 준비

먼저 `app.log` 파일을 만든다.

파일명: `app.log`

```
2026-04-20 10:01:11 INFO service started
2026-04-20 10:01:15 ERROR database connection failed
2026-04-20 10:01:20 INFO retry started
2026-04-20 10:01:25 ERROR timeout occurred
2026-04-20 10:01:30 INFO service stopped
```

이 파일은 간단한 애플리케이션 로그를 가정한 것이다.

---

## 2. 로그 파일 전체 읽기

파일명: `read_log_all.py`

```
with open("app.log","r",encoding="utf-8") as file:
	for line in file:
		print(line.strip())
```

실행한다.

```
python read_log_all.py
```

실행 결과는 다음과 같다.

```
2026-04-20 10:01:11 INFO service started
2026-04-20 10:01:15 ERROR database connection failed
2026-04-20 10:01:20 INFO retry started
2026-04-20 10:01:25 ERROR timeout occurred
2026-04-20 10:01:30 INFO service stopped
```

---

## 3. 코드 설명

```
with open("app.log","r",encoding="utf-8") as file:
```

`open()`은 파일을 여는 함수이다.

첫 번째 인자인 `"app.log"`는 열 파일 이름이다.

두 번째 인자인 `"r"`은 읽기 모드이다. `r`은 read를 의미한다.

세 번째 인자인 `encoding="utf-8"`은 파일을 UTF-8 문자 인코딩으로 읽겠다는 의미이다. 한글 로그가 포함될 수 있으므로 UTF-8을 명시하는 것이 좋다.

```
for line in file:
```

파일 객체를 반복문에 넣으면 파일을 한 줄씩 읽는다.

로그 파일은 보통 줄 단위로 기록되기 때문에 `for line in file:` 구조가 로그 분석에 매우 자주 사용된다.

```
print(line.strip())
```

`strip()`은 문자열 앞뒤의 공백, 탭, 줄바꿈 문자를 제거한다.

파일을 한 줄씩 읽으면 각 줄 끝에는 줄바꿈 문자 `\n`이 포함된다.

예를 들어 다음 로그 한 줄이 있다고 하자.

```
2026-04-20 10:01:11 INFO service started
```

Python이 파일에서 이 줄을 읽으면 내부적으로는 다음과 비슷한 문자열이 된다.

```
"2026-04-20 10:01:11 INFO service started\n"
```

여기서 `\n`은 줄바꿈 문자이다.

따라서 출력할 때 깔끔하게 보이도록 `strip()`을 사용한다.

# 6.4 특정 키워드가 포함된 로그 찾기

## 1. 문자열 포함 여부 확인

Python에서는 문자열 안에 특정 문자열이 포함되어 있는지 `in`으로 확인할 수 있다.

예를 들면 다음과 같다.

```
line="2026-04-20 10:01:15 ERROR database connection failed"

if "ERROR" in line:
	print("ERROR 로그입니다.")
```

`"ERROR" in line`은 `line` 문자열 안에 `"ERROR"`라는 문자열이 포함되어 있으면 `True`가 된다.

---

## 2. ERROR 로그만 출력하기

파일명: `read_error_only.py`

```
with open("app.log","r",encoding="utf-8") as file:
	for line in file:
		if "ERROR" in line:
			print(f"error line:{line.strip()}")
```

실행한다.

```
python read_error_only.py
```

실행 결과는 다음과 같다.

```
error line: 2026-04-20 10:01:15 ERROR database connection failed
error line: 2026-04-20 10:01:25 ERROR timeout occurred
```

---

## 3. 코드 설명

```
if "ERROR" in line:
```

이 조건은 현재 읽은 줄에 `ERROR`라는 문자열이 포함되어 있는지 검사한다.

포함되어 있으면 아래 코드가 실행된다.

```
print(f"error line:{line.strip()}")
```

`f-string`을 사용해 출력 문자열 안에 로그 내용을 넣는다.

---

## 4. 단순 문자열 검색의 한계

`if "ERROR" in line:` 방식은 쉽고 빠르다.

하지만 모든 상황에서 정확하지는 않다.

예를 들어 다음 로그를 보자.

```
2026-04-20 10:02:00 INFO previous_error_count=0
2026-04-20 10:02:10 INFO message=NOERROR
```

이 로그는 실제 오류 로그가 아니지만 `ERROR`라는 문자열이 포함되어 있을 수 있다.

따라서 단순 문자열 검색은 빠르게 확인할 때는 좋지만, 정확한 분석이 필요할 때는 로그 형식에 맞게 처리하는 것이 좋다.

예를 들어 로그 레벨 위치가 일정하다면 다음처럼 분리해서 검사할 수 있다.

```
line="2026-04-20 10:01:15 ERROR database connection failed"
parts=line.split()

level=parts[2]

if level=="ERROR":
	print("정확한 ERROR 로그")
```

`split()`은 문자열을 공백 기준으로 나누어 리스트로 만든다.

위 로그를 `split()`하면 다음과 비슷한 결과가 된다.

```
[
"2026-04-20",
"10:01:15",
"ERROR",
"database",
"connection",
"failed"
]
```

여기서 인덱스 `2`에 해당하는 값이 로그 레벨이다.

# 6.5 조건문과 반복문을 이용한 로그 분기

## 1. 로그 레벨별로 다르게 출력하기

로그에는 `INFO`, `WARN`, `ERROR` 같은 레벨이 있다.

각 레벨에 따라 다른 형식으로 출력해보자.

파일명: `log_level_branch.py`

```
with open("app.log", "r", encoding="utf-8") as file:
    for line in file:
        line = line.strip()
        
        # 빈 줄은 처리하지 않고 건너뛴다.
        if not line:
            continue

        if "ERROR" in line:
            print(f"[ERROR] {line}")
        elif "WARN" in line:
            print(f"[WARN] {line}")
        elif "INFO" in line:
            print(f"[INFO] {line}")
        else:
            print(f"[OTHER] {line}")
```

실행한다.

```
python log_level_branch.py
```

실행 결과는 다음과 같다.

```

[ERROR] 2026-04-20 10:01:15 ERROR database connection failed
[INFO] 2026-04-20 10:01:20 INFO retry started
[ERROR] 2026-04-20 10:01:25 ERROR timeout occurred
[INFO] 2026-04-20 10:01:30 INFO service stopped
```

---

## 2. 코드 설명

```
if"ERROR"inline:
```

먼저 `ERROR`가 포함되어 있는지 확인한다.

```
elif"WARN"inline:
```

앞의 조건이 아니면 `WARN`이 포함되어 있는지 확인한다.

```
elif"INFO"inline:
```

앞의 조건들이 모두 아니면 `INFO`가 포함되어 있는지 확인한다.

```
else:
```

위 조건에 모두 해당하지 않는 로그는 `OTHER`로 처리한다.

이 구조는 로그를 레벨별로 분리하거나, 상태별로 다른 처리를 할 때 기본적으로 사용된다.

# 6.6 정규표현식 기초

## 1. 정규표현식이 필요한 이유

단순 문자열 검색만으로는 부족한 경우가 많다.

예를 들어 다음 값들을 정확히 추출하고 싶을 수 있다.

* 상태코드

* IP 주소

* 요청 경로

* 날짜

* 시간

* 숫자 값

* 특정 패턴의 메시지

이런 경우 정규표현식을 사용한다.

정규표현식은 문자열에서 특정 규칙을 가진 부분을 찾기 위한 표현식이다.

Python에서는 `re` 모듈을 사용한다.

```
importre
```

---

## 2. 자주 사용하는 정규표현식 패턴

| 패턴 | 의미 | 예시 |
| --- | --- | --- |
| `\d` | 숫자 한 글자 | `1`, `5`, `9` |
| `\d+` | 숫자가 1개 이상 반복 | `500`, `1234` |
| `\d{3}` | 숫자가 정확히 3개 | `200`, `404`, `500` |
| `.` | 임의의 문자 한 글자 | `a`, `1`, `?` |
| `.*` | 임의의 문자가 0개 이상 반복 | 여러 문자 |
| `()` | 추출할 부분을 그룹으로 지정 | 상태코드만 추출 |
| `^` | 문자열 시작 | 로그 시작 부분 |
| `$` | 문자열 끝 | 로그 끝 부분 |
| `[^ ]+` | 공백이 아닌 문자가 1개 이상 반복 | `/api/items` |

---

## 3. 숫자 찾기 예제

파일명: `regex_number.py`

```
import re

line="status=500"

match=re.search(r"\d+",line)

if match:
	print(match.group())
```

실행한다.

```
python regex_number.py
```

실행 결과는 다음과 같다.

```
500
```

---

## 4. 코드 설명

```
match=re.search(r"\d+",line)
```

`re.search()`는 문자열 안에서 정규표현식 패턴과 일치하는 부분을 찾는다.

`r"\d+"`는 숫자가 하나 이상 이어진 부분을 찾는 패턴이다.

여기서 앞에 붙은 `r`은 raw string을 의미한다.

정규표현식에서는 `\d`처럼 역슬래시를 많이 사용한다. 그래서 Python 문자열에서 역슬래시를 그대로 사용하기 위해 `r"..."` 형태를 자주 사용한다.

```
if match:
```

패턴을 찾으면 `match` 객체가 만들어진다.

찾지 못하면 `None`이 된다.

따라서 `match.group()`을 사용하기 전에 반드시 `if match:`로 확인하는 것이 안전하다.

```
print(match.group())
```

`group()`은 실제로 찾은 문자열을 반환한다.

---

## 5. 상태코드 추출 예제

웹 액세스 로그에서 상태코드를 추출해보자.

```
127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 500 1234
```

이 로그에서 상태코드는 `500`이다.

파일명: `regex_status_code.py`

```
import re

line='127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 500 1234'

match=re.search(r'" (\d{3}) ',line)

if match:
	print(match.group(1))
```

실행한다.

```
python regex_status_code.py
```

실행 결과는 다음과 같다.

```
500
```

---

## 6. `group()`과 `group(1)`의 차이

다음 패턴을 보자.

```
r'" (\d{3}) '
```

이 패턴의 의미는 다음과 같다.

| 부분 | 의미 |
| --- | --- |
| `"` | 큰따옴표 문자를 찾음 |
| 공백 | 큰따옴표 뒤의 공백 |
| `(\d{3})` | 숫자 3개를 찾아 그룹으로 묶음 |
| 공백 | 상태코드 뒤의 공백 |

`group()`은 패턴 전체와 일치한 문자열을 반환한다.

`group(1)`은 괄호 `()`로 묶은 첫 번째 그룹만 반환한다.

예를 들어 다음 코드를 보자.

```
import re

line='127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 500 1234'

match=re.search(r'" (\d{3}) ',line)

if match:
	print(match.group())
	print(match.group(1))
```

실행 결과는 다음과 같다.

```
" 500
500
```

첫 번째 출력은 패턴 전체이고, 두 번째 출력은 괄호로 묶은 상태코드만 출력한 것이다.

# 6.7 액세스 로그 기초 분석

## 1. 실습 파일 준비

파일명: `access.log`

```
127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 200 1234
10.0.1.15 - - [20/Apr/2026:10:01:20 +0900] "POST /login HTTP/1.1" 401 532
10.0.1.16 - - [20/Apr/2026:10:01:25 +0900] "GET /admin HTTP/1.1" 403 222
10.0.1.17 - - [20/Apr/2026:10:01:30 +0900] "GET /api/items HTTP/1.1" 500 110
127.0.0.1 - - [20/Apr/2026:10:01:35 +0900] "GET /health HTTP/1.1" 200 15
```

이 파일은 웹 서버의 액세스 로그를 단순화한 예제이다.

각 줄에는 IP, 시간, 요청 메서드, 요청 경로, 상태코드, 응답 크기가 포함되어 있다.

---

## 2. 4xx, 5xx 로그만 출력하기

HTTP 상태코드는 응답 결과를 나타낸다.

대표적으로 다음과 같다.

| 상태코드 범위 | 의미 |
| --- | --- |
| `2xx` | 성공 |
| `3xx` | 리다이렉션 |
| `4xx` | 클라이언트 오류 |
| `5xx` | 서버 오류 |

운영에서는 특히 `4xx`, `5xx`를 자주 확인한다.

파일명: `access_error_filter.py`

```
import re

with open("access.log","r",encoding="utf-8") as file:
	for line in file:
		match=re.search(r'" (\d{3}) ',line)

		if match:
			status_code=match.group(1)

		if status_code.startswith("4") or status_code.startswith("5"):
			print(line.strip())
```

실행한다.

```
python access_error_filter.py
```

실행 결과는 다음과 같다.

```
10.0.1.15 - - [20/Apr/2026:10:01:20 +0900] "POST /login HTTP/1.1" 401 532
10.0.1.16 - - [20/Apr/2026:10:01:25 +0900] "GET /admin HTTP/1.1" 403 222
10.0.1.17 - - [20/Apr/2026:10:01:30 +0900] "GET /api/items HTTP/1.1" 500 110
```

---

## 3. 코드 설명

```
match=re.search(r'" (\d{3}) ',line)
```

액세스 로그에서 상태코드 부분을 찾는다.

```
status_code=match.group(1)
```

괄호로 묶은 상태코드만 추출한다.

```
if status_code.startswith("4") or status_code.startswith("5"):
```

`startswith()`는 문자열이 특정 문자로 시작하는지 확인한다.

`"401".startswith("4")`는 `True`이다.

`"500".startswith("5")`도 `True`이다.

따라서 이 조건은 4xx 또는 5xx 상태코드만 찾는다.

# 6.8 기본 집계

## 1. ERROR 로그 개수 세기

로그 분석의 기본은 개수를 세는 것이다.

파일명: `error_count.py`

```
error_count=0

with open("app.log","r",encoding="utf-8") as file:
	for line in file:
		if "ERROR" in line:
			error_count += 1

	print(f"error count:{error_count}")
```

실행한다.

```
python error_count.py
```

실행 결과는 다음과 같다.

```
error count: 2
```

---

## 2. 코드 설명

```
error_count=0
```

오류 로그 개수를 저장할 변수를 만든다.

처음에는 아직 찾은 오류가 없으므로 `0`으로 시작한다.

```
if "ERROR" in line:
	error_count += 1
```

현재 줄에 `ERROR`가 포함되어 있으면 `error_count` 값을 1 증가시킨다.

```
error_count += 1
```

이 코드는 다음 코드와 같은 의미이다.

```
error_count = error_count + 1
```

---

## 3. 상태코드별 개수 세기

이번에는 액세스 로그에서 상태코드별 개수를 세어보자.

파일명: `status_count.py`

```
import re

status_count= {}

with open("access.log","r",encoding="utf-8") as file:
	for line in file:
		match=re.search(r'" (\d{3}) ',line)

		if match:
			status_code=match.group(1)

			if status_code not in status_count:
				status_count[status_code]=0

			status_count[status_code] += 1

	print(status_count)
```

실행한다.

```
python status_count.py
```

실행 결과는 다음과 같다.

```
{'200': 2, '401': 1, '403': 1, '500': 1}
```

---

## 4. 딕셔너리를 집계에 사용하는 방식

`status_count` 딕셔너리는 상태코드를 키로, 개수를 값으로 저장한다.

```
{
"200":2,
"401":1,
"403":1,
"500":1
}
```

예를 들어 상태코드 `200`이 나오면 다음처럼 저장된다.

```
status_count["200"]=1
```

다시 `200`이 나오면 값이 증가한다.

```
status_count["200"]+=1
```

다만 처음 등장한 상태코드는 아직 딕셔너리에 없으므로 먼저 초기화해야 한다.

```
if status_code not in status_count:
	status_count[status_code] = 0
```

이 코드는 상태코드가 처음 등장했을 때 개수를 0으로 준비하는 역할을 한다.

---

## 5. Counter를 이용한 상태코드 집계

Python의 `collections` 모듈에는 개수를 세기 좋은 `Counter`가 있다.

직접 딕셔너리를 만들고 초기화하지 않아도 된다.

파일명: `status_count_counter.py`

```
import re
from collections import Counter

status_counter = Counter()

with open("access.log", "r", encoding="utf-8") as file:
    for line in file:
        match = re.search(r'" (\d{3}) ', line)
        if match:
            status_code = match.group(1)
            # Counter는 키가 없어도 자동으로 0으로 처리하므로 바로 더하면 됩니다.
            status_counter[status_code] += 1

print("상태코드별 개수")

for status_code, count in sorted(status_counter.items()):
    print(f"{status_code}: {count}")
```

실행한다.

```
python status_count_counter.py
```

실행 결과는 다음과 같다.

```
상태코드별 개수
200: 2
401: 1
403: 1
500: 1
```

`Counter`는 로그 분석처럼 특정 값이 몇 번 나왔는지 세는 작업에 적합하다.

# 6.9 IP별 요청 수 집계

## 1. IP별 요청 수가 필요한 이유

액세스 로그에서는 어떤 IP가 많이 요청했는지도 중요하다.

특정 IP가 비정상적으로 많은 요청을 보내면 다음과 같은 상황일 수 있다.

* 크롤러 접근

* 스캐닝 시도

* 로그인 공격

* 비정상 API 반복 호출

* 특정 사용자 트래픽 집중

따라서 IP별 요청 수 집계는 운영 분석에서 자주 사용된다.

---

## 2. IP 주소 추출 방식

액세스 로그는 보통 IP 주소가 맨 앞에 나온다.

예를 들어 다음 로그를 보자.

```
10.0.1.15 - - [20/Apr/2026:10:01:20 +0900] "POST /login HTTP/1.1" 401 532
```

이 로그를 공백 기준으로 나누면 첫 번째 값이 IP 주소이다.

```
line='10.0.1.15 - - [20/Apr/2026:10:01:20 +0900] "POST /login HTTP/1.1" 401 532'

parts=line.split()
print(parts[0])
```

실행 결과는 다음과 같다.

```
10.0.1.15
```

---

## 3. IP별 요청 수 집계 코드

파일명: `ip_count.py`

```
from collections import Counter

ip_counter = Counter()

with open("access.log", "r", encoding="utf-8") as file:
    for line in file:
        parts = line.split()
        
        if parts:
            ip = parts[0]
            ip_counter[ip] += 1

print("IP별 요청 수")

for ip, count in ip_counter.items():
    print(f"{ip}: {count}")
```

실행한다.

```
python ip_count.py
```

실행 결과는 다음과 같다.

```
IP별 요청 수
127.0.0.1: 2
10.0.1.15: 1
10.0.1.16: 1
10.0.1.17: 1
```

---

## 4. 코드 설명

```
parts=line.split()
```

로그 한 줄을 공백 기준으로 나눈다.

```
if parts:
```

빈 줄이면 `parts`가 빈 리스트가 될 수 있다.

빈 리스트에서 `parts[0]`을 실행하면 오류가 발생한다.

따라서 값이 있는지 먼저 확인한다.

```
ip=parts[0]
```

첫 번째 값을 IP 주소로 사용한다.

```
ip_counter[ip]+=1
```

IP 주소별 요청 수를 증가시킨다.

# 6.10 요청 경로별 집계

## 1. 요청 경로별 집계가 필요한 이유

액세스 로그에서는 어떤 URL 또는 API가 많이 호출되었는지도 중요하다.

예를 들어 다음을 확인할 수 있다.

* `/api/items` 요청이 많은가

* `/login` 요청이 반복적으로 실패하는가

* `/admin` 접근 시도가 있는가

* `/health` 체크 요청이 정상적으로 들어오는가

* 특정 API에서 500 오류가 집중되는가

요청 경로별 집계는 서비스 사용 패턴 분석과 장애 분석에 모두 유용하다.

---

## 2. 요청 경로 추출하기

다음 로그를 보자.

```
127.0.0.1 - - [20/Apr/2026:10:01:15 +0900] "GET /api/items HTTP/1.1" 200 1234
```

요청 정보는 큰따옴표 안에 있다.

```
"GET /api/items HTTP/1.1"
```

여기서 요청 경로는 `/api/items`이다.

---

## 3. 요청 경로별 집계 코드

파일명: `path_count.py`

```
import re
from collections import Counter

path_counter = Counter()

with open("access.log", "r", encoding="utf-8") as file:
    for line in file:
        # 요청 경로(Path)를 추출하기 위한 정규표현식 매칭
        match = re.search(r'"[A-Z]+ ([^ ]+) HTTP/', line)

        if match:
            path = match.group(1)
            path_counter[path] += 1

print("요청 경로별 개수")

for path, count in path_counter.items():
    print(f"{path}: {count}")
```

실행한다.

```
python path_count.py
```

실행 결과는 다음과 같다.

```
요청 경로별 개수
/api/items: 2
/login: 1
/admin: 1
/health: 1
```

---

## 4. 정규표현식 설명

사용한 패턴은 다음과 같다.

```
r'"[A-Z]+ ([^ ]+) HTTP/'
```

각 부분의 의미는 다음과 같다.

| 패턴 | 의미 |
| --- | --- |
| `"` | 요청 정보가 시작되는 큰따옴표 |
| `[A-Z]+` | GET, POST 같은 대문자 메서드 |
| 공백 | 메서드와 경로 사이의 공백 |
| `([^ ]+)` | 공백이 아닌 문자열을 추출 |
| 공백 | 경로와 HTTP 버전 사이의 공백 |
| `HTTP/` | HTTP 버전 시작 부분 |

`([^ ]+)`가 요청 경로를 추출하는 핵심 부분이다.

`[]` 안의 `^`는 “아닌 것”을 의미한다.

따라서 `[^ ]+`는 “공백이 아닌 문자가 하나 이상 반복”이라는 뜻이다.

# 6.11 시간대별 집계 기초

## 1. 시간대별 집계가 필요한 이유

운영 환경에서는 특정 시간대에 요청이나 오류가 집중되는지 확인해야 할 때가 많다.

예를 들어 다음과 같은 질문을 할 수 있다.

* 오전 10시에 오류가 집중되었는가

* 특정 시간대에 요청 수가 급증했는가

* 배포 직후 500 오류가 증가했는가

* 야간 시간대에 비정상 접근이 있었는가

처음부터 복잡한 시간 파싱을 하지 않아도, 로그 문자열 일부를 잘라 시간대별 집계를 할 수 있다.

---

## 2. 텍스트 로그 시간대별 집계

`app.log`의 한 줄은 다음과 같다.

```
2026-04-20 10:01:11 INFO service started
```

앞에서 13글자를 자르면 다음 값이 된다.

```
2026-04-20 10
```

이 값을 집계 키로 사용하면 날짜와 시간 단위로 묶을 수 있다.

파일명: `hour_count.py`

```
hour_count = {}

with open("app.log", "r", encoding="utf-8") as file:
    for line in file:
        # 시간대 키 추출 (예: 2026-05-04 12)
        hour_key = line[:13]

        if hour_key not in hour_count:
            hour_count[hour_key] = 0
        
        # 1을 더하는 로직은 if문 밖에 있어야 누적됨
        hour_count[hour_key] += 1

# 모든 로그 처리가 끝난 후 한 번만 출력
for hour, count in hour_count.items():
    print(f"{hour}: {count}")
```

실행한다.

```
python hour_count.py
```

실행 결과는 다음과 같다.

```
2026-04-20 10: 5
```

---

## 3. 코드 설명

```
hour_key=line[:13]
```

문자열 슬라이싱을 사용한다.

`line[:13]`은 문자열의 처음부터 인덱스 13 이전까지 가져온다.

로그 형식이 일정하다면 이렇게 문자열 일부를 잘라 간단히 집계할 수 있다.

다만 이 방식은 로그 형식이 바뀌면 정확하지 않을 수 있다.

운영 환경에서는 로그 형식이 일정한지 먼저 확인해야 한다.

```
{'time': '2026-04-20T10:01:20', 'level': 'INFO', 'message': 'retry started'}
{'time': '2026-04-20T10:01:25', 'level': 'ERROR', 'message': 'timeout occurred'}
```

---

## 3. 코드 설명

```
importjson
```

JSON 문자열을 Python 객체로 변환하기 위해 `json` 모듈을 가져온다.

```
log=json.loads(line)
```

`json.loads()`는 문자열 형태의 JSON을 Python 딕셔너리로 변환한다.

예를 들어 다음 JSON 문자열은

```
{"time":"2026-04-20T10:01:11","level":"INFO","message":"service started"}
```

Python에서는 다음 딕셔너리처럼 다룰 수 있다.

```
{
	"time":"2026-04-20T10:01:11",
	"level":"INFO",
	"message":"service started"
}
```

---

## 4. JSON 로그에서 ERROR만 출력하기

파일명: `json_log_filter.py`

```
import json

with open("app_json.log", "r", encoding="utf-8") as file:
    for line in file:
        # JSON 형식의 문자열을 파이썬 딕셔너리로 변환
        log = json.loads(line)

        # 로그 레벨이 ERROR인 경우에만 특정 필드 출력
        if log["level"] == "ERROR":
            print(f"time={log['time']}, message={log['message']}")
```

실행한다.

```
python json_log_filter.py
```

실행 결과는 다음과 같다.

```
time=2026-04-20T10:01:15, message=database connection failed
time=2026-04-20T10:01:25, message=timeout occurred
```

---

## 5. `log["level"]`과 `log.get("level")`의 차이

딕셔너리에서 값을 가져오는 방법은 크게 두 가지가 있다.

```
log["level"]
```

이 방식은 `level` 키가 반드시 있다고 가정한다.

만약 `level` 키가 없으면 오류가 발생한다.

```
log.get("level")
```

이 방식은 `level` 키가 없으면 `None`을 반환한다.

그래서 로그 형식이 완전히 일정하지 않을 수 있는 경우에는 `get()`을 사용하는 것이 더 안전하다.

```
if log.get("level") == "ERROR":
	print(log.get("message"))
```

# 6.13 잘못된 JSON 로그 건너뛰기

## 1. 잘못된 로그 줄이 섞이는 경우

실제 운영 환경에서는 로그 파일의 모든 줄이 정상 형식이라고 보장할 수 없다.

예를 들어 JSON 로그 파일에 다음처럼 잘못된 줄이 섞일 수 있다.

파일명: `app_json_invalid.log`

```
{"time":"2026-04-20T10:01:11","level":"INFO","message":"service started"}
INVALID JSON LINE
{"time":"2026-04-20T10:01:15","level":"ERROR","message":"database connection failed"}
{"time":"2026-04-20T10:01:25","level":"ERROR","message":"timeout occurred"}
```

이 상태에서 `json.loads()`를 그대로 사용하면 `INVALID JSON LINE`에서 오류가 발생한다.

운영 자동화 스크립트에서는 잘못된 한 줄 때문에 전체 분석이 중단되지 않도록 처리하는 것이 좋다.

---

## 2. 잘못된 JSON 줄 건너뛰기

파일명: `json_log_safe_parse.py`

```
import json

with open("app_json_invalid.log", "r", encoding="utf-8") as file:
    for line_number, line in enumerate(file, start=1):
        line = line.strip()

        if not line:
            continue

        try:
            # JSON 파싱 시도
            log = json.loads(line)
        except json.JSONDecodeError:
            # 형식이 잘못된 경우 에러 메시지 출력 후 다음 줄로 이동
            print(f"{line_number}번째 줄은 JSON 형식이 아니어서 건너뜀")
            continue

        # level이 ERROR인 경우에만 안전하게(get 메서드 사용) 필드 값 출력
        if log.get("level") == "ERROR":
            print(f"time={log.get('time')}, message={log.get('message')}")
```

실행한다.

```
python json_log_safe_parse.py
```

실행 결과는 다음과 같다.

```
2번째 줄은 JSON 형식이 아니어서 건너뜀
time=2026-04-20T10:01:15, message=database connection failed
time=2026-04-20T10:01:25, message=timeout occurred
```

---

## 3. 코드 설명

```
for line_number,line in enumerate(file,start=1):
```

`enumerate()`는 반복문에서 인덱스와 값을 함께 가져온다.

`start=1`을 사용하면 줄 번호를 1부터 시작한다.

```
if not line:
	continue
```

빈 줄이면 처리하지 않고 다음 줄로 넘어간다.

`continue`는 현재 반복을 건너뛰고 다음 반복으로 이동한다.

```
try:
	log = json.loads(line)
except json.JSONDecodeError:
```

JSON 파싱 중 오류가 발생하면 `except` 블록이 실행된다.

```
continue
```

잘못된 줄은 건너뛰고 다음 로그 줄을 계속 처리한다.

이 구조는 운영 자동화에서 매우 중요하다.

오류가 일부 있어도 전체 분석은 계속 진행되어야 하기 때문이다.

# 6.14 에러 줄만 파일로 저장하기

## 1. 분석 결과를 파일로 저장하는 이유

로그 분석 결과는 화면에 출력하는 것만으로 끝나지 않을 수 있다.

운영 환경에서는 필터링한 결과를 별도 파일로 저장해 다음 작업에 활용할 수 있다.

예를 들어 다음과 같은 작업이 가능하다.

* ERROR 로그만 별도 파일로 저장

* 500 오류 로그만 저장

* 특정 IP의 요청만 저장

* 장애 시간대 로그만 저장

* 분석 결과를 보고서 파일로 저장

---

## 2. ERROR 로그만 저장하기

파일명: `save_error_only.py`

```
with open("app.log", "r", encoding="utf-8") as file, \
     open("error_only.log", "w", encoding="utf-8") as output_file:

    for line in file:
        # 줄 바꿈 기호를 포함한 한 줄 단위로 처리
        if "ERROR" in line:
            # "ERROR" 단어가 포함된 줄만 결과 파일에 기록
            output_file.write(line)
```

실행한다.

```
python save_error_only.py
```

실행 후 `error_only.log` 파일이 생성된다.

파일 내용은 다음과 같다.

```

2026-04-20 10:01:25 ERROR timeout occurred
```

---

## 3. 코드 설명

```
with open("app.log","r",encoding="utf-8") as file, \
open("error_only.log","w",encoding="utf-8") as output_file:
```

두 개의 파일을 동시에 연다.

* `app.log`는 읽기 모드

* `error_only.log`는 쓰기 모드

```
output_file.write(line)
```

조건에 맞는 로그 줄을 파일에 쓴다.

`line`에는 원래 줄바꿈 문자가 포함되어 있으므로 별도로 `\n`을 추가하지 않아도 된다.

# 6.15 예외 처리 추가하기

# 6.16 실행 인자로 파일명과 키워드 받기

## 1. 실행 인자가 필요한 이유

지금까지 작성한 코드는 파일명이 코드 안에 고정되어 있었다.

예를 들어 다음 코드에서는 항상 `app.log`만 읽는다.

```
with open("app.log","r",encoding="utf-8") as file:
```

하지만 운영 환경에서는 분석할 파일명이 매번 다를 수 있다.

예를 들어 다음과 같은 파일을 분석할 수 있다.

```
app.log
app-2026-04-20.log
access.log
access-2026-04-20.log
error.log
```

이럴 때 파일명을 코드에 직접 고정하면 매번 코드를 수정해야 한다.

자동화 스크립트에서는 실행할 때 파일명을 인자로 받는 방식이 좋다.

---

## 2. argparse 기본 구조

Python에서는 명령행 인자를 처리할 때 `argparse` 모듈을 많이 사용한다.

파일명: `log_keyword_search.py`

```
import argparse

parser = argparse.ArgumentParser(description="로그 파일에서 특정 키워드가 포함된 줄을 검색한다.")
parser.add_argument("--file", required=True, help="분석할 로그 파일 경로")
parser.add_argument("--keyword", required=True, help="검색할 키워드")

args = parser.parse_args()

try:
    with open(args.file, "r", encoding="utf-8") as file:
        for line in file:
            if args.keyword in line:
                print(line.strip())

except FileNotFoundError:
    print(f"파일을 찾을 수 없음: {args.file}")

except Exception as e:
    print("로그 검색 중 오류 발생")
    print(f"오류 내용: {e}")
```

실행한다.

```
python log_keyword_search.py --file app.log --keyword ERROR
```

실행 결과는 다음과 같다.

```
2026-04-20 10:01:15 ERROR database connection failed
2026-04-20 10:01:25 ERROR timeout occurred
```

---

## 3. 코드 설명

```
parser=argparse.ArgumentParser(description="로그 파일에서 특정 키워드가 포함된 줄을 검색한다.")
```

명령행 인자를 처리할 파서를 만든다.

`description`은 이 스크립트가 어떤 역할을 하는지 설명한다.

```
parser.add_argument("--file",required=True,help="분석할 로그 파일 경로")
```

* `-file` 인자를 추가한다.

`required=True`는 이 인자를 반드시 입력해야 한다는 의미이다.

```
parser.add_argument("--keyword",required=True,help="검색할 키워드")
```

* `-keyword` 인자를 추가한다.

```
args=parser.parse_args()
```

실행 시 입력한 인자를 읽어온다.

```
args.file
```

# 6.18 자동화 스타일 종합 예제

## 1. 실습 목표

이번 실습에서는 `access.log` 파일을 분석해서 요약 리포트를 출력하는 자동화 스크립트를 작성한다.

분석 항목은 다음과 같다.

* 전체 요청 수

* 상태코드별 요청 수

* 4xx 요청 수

* 5xx 요청 수

* IP별 요청 수

* 요청 경로별 요청 수

* 형식이 맞지 않는 로그 줄 수

이 예제는 단순히 로그를 읽는 수준을 넘어 운영 자동화 스크립트 구조에 가깝게 작성한다.

---

## 2. 최종 코드

파일명: `access_log_report.py`

```
import re
import argparse
from collections import Counter


def parse_access_log_line(line):
    """
    access.log 한 줄에서 IP, 요청 경로, 상태코드를 추출한다.
    정상적으로 추출하면 딕셔너리를 반환한다.
    형식이 맞지 않으면 None을 반환한다.
    """

    pattern = r'^([^ ]+) .* "\w+ ([^ ]+) HTTP/[^"]+" (\d{3}) '
    match = re.search(pattern, line)

    if not match:
        return None

    return {
        "ip": match.group(1),
        "path": match.group(2),
        "status_code": match.group(3)
    }


def analyze_access_log(filename):
    """
    access.log 파일 전체를 읽고 주요 항목을 집계한다.
    """

    total_count = 0
    status_counter = Counter()
    ip_counter = Counter()
    path_counter = Counter()
    client_error_count = 0
    server_error_count = 0
    invalid_line_count = 0

    with open(filename, "r", encoding="utf-8") as file:
        for line in file:
            parsed = parse_access_log_line(line)

            if parsed is None:
                invalid_line_count += 1
                continue

            total_count += 1

            ip = parsed["ip"]
            path = parsed["path"]
            status_code = parsed["status_code"]

            status_counter[status_code] += 1
            ip_counter[ip] += 1
            path_counter[path] += 1

            if status_code.startswith("4"):
                client_error_count += 1
            elif status_code.startswith("5"):
                server_error_count += 1

    return {
        "total_count": total_count,
        "status_counter": status_counter,
        "ip_counter": ip_counter,
        "path_counter": path_counter,
        "client_error_count": client_error_count,
        "server_error_count": server_error_count,
        "invalid_line_count": invalid_line_count
    }


def print_report(result):
    """
    분석 결과를 보기 좋은 형식으로 출력한다.
    """

    print("===== Access Log Summary =====")
    print(f"전체 요청 수: {result['total_count']}")
    print(f"4xx 요청 수: {result['client_error_count']}")
    print(f"5xx 요청 수: {result['server_error_count']}")
    print(f"형식 오류 줄 수: {result['invalid_line_count']}")
    print()

    print("[상태코드별 요청 수]")
    for status_code, count in result["status_counter"].items():
        print(f"{status_code}: {count}")

    print()
    print("[IP별 요청 수]")
    for ip, count in result["ip_counter"].items():
        print(f"{ip}: {count}")

    print()
    print("[요청 경로별 요청 수]")
    for path, count in result["path_counter"].items():
        print(f"{path}: {count}")


def main():
    parser = argparse.ArgumentParser(
        description="access.log 파일을 분석해서 요약 리포트를 출력한다."
    )

    parser.add_argument(
        "--file",
        required=True,
        help="분석할 access.log 파일 경로"
    )

    args = parser.parse_args()

    try:
        result = analyze_access_log(args.file)
        print_report(result)

    except FileNotFoundError:
        print(f"파일을 찾을 수 없음: {args.file}")

    except Exception as e:
        print("로그 분석 중 오류 발생")
        print(f"오류 내용: {e}")


if __name__ == "__main__":
    main()
```

# 6.20 정리

이 장에서는 Python을 사용해 로그 파일을 분석하는 기본 흐름을 학습했다.

핵심 내용은 다음과 같다.

* 로그는 시스템과 애플리케이션의 동작 기록이다.

* 운영 환경에서는 로그를 통해 장애 원인, 오류 빈도, 요청 패턴을 확인한다.

* Python에서는 `open()`과 반복문을 사용해 로그 파일을 줄 단위로 읽을 수 있다.

* `strip()`은 줄 끝의 줄바꿈 문자를 제거할 때 사용한다.

* `in`을 사용하면 특정 키워드가 포함된 로그만 찾을 수 있다.

* 단순 문자열 검색은 쉽지만 정확한 분석에는 한계가 있다.

* 정규표현식을 사용하면 상태코드, IP, 요청 경로 같은 값을 추출할 수 있다.

* 딕셔너리와 `Counter`는 로그 집계에 유용하다.

* JSON 로그는 `json.loads()`로 파싱한 뒤 딕셔너리처럼 다룰 수 있다.

* 잘못된 JSON 줄은 예외 처리로 건너뛸 수 있다.

* `argparse`를 사용하면 파일명이나 키워드를 실행 인자로 받을 수 있다.

* 함수 분리, 예외 처리, 실행 인자 처리를 포함하면 운영 자동화 스크립트에 가까운 형태가 된다.
