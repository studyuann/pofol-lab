1장 클라우드 개요

1.1 IT 인프라의 변화

초기의 IT 서비스는 온프레미스(On-Premise) 환경에서 운영했음.

온프레미스는 기업이 직접 IT 인프라를 구축하고 운영하는 방식이다.

예를 들어 기업이 웹 서비스를 운영하려면 다음 장비가 필요했음.

  • 서버
  • 스토리지
  • 네트워크 장비
  • 방화벽
  • 데이터센터 시설

즉 서비스를 운영하기 위해 물리적인 장비를 직접 구매하고 설치해야 했음.

구조를 간단히 표현하면 다음과 같다.

사용자
  │
인터넷
  │
방화벽
  │
웹 서버
  │
데이터베이스 서버
  │
스토리지

이 구조에서는 기업이 모든 인프라를 직접 관리해야 했음.

예를 들어 다음 작업이 필요하다.

  • 서버 설치
  • 운영체제 설치
  • 네트워크 설정
  • 보안 설정
  • 백업 관리
  • 장애 대응

즉 서비스 운영 이전에 인프라 구축에 많은 시간과 비용이 필요했음.

1.2 온프레미스 환경의 문제점

온프레미스 환경에는 여러 가지 문제가 존재한다.

1) 높은 초기 비용

서비스를 시작하려면 먼저 장비를 구매해야 한다.

예를 들어 웹 서비스를 구축한다고 가정해 보자.

필요한 장비 예시

  • 웹 서버 2대
  • DB 서버 1대
  • 스토리지
  • 네트워크 장비

이 장비를 모두 구매해야 한다.

예시 비용

서버 3대
스토리지
네트워크 장비
데이터센터 공간

즉 서비스를 시작하기 전부터 큰 비용이 발생함.

2) 확장 어려움

서비스가 성장하면 사용자가 증가한다.

예를 들어 다음과 같은 상황이 발생할 수 있다.

초기 사용자 : 100명
성장 후 사용자 : 10,000명

사용자가 증가하면 서버가 부족해진다.

이 경우 기업은 다음 작업을 해야 한다.

서버 구매
→ 배송
→ 설치
→ 운영체제 설치
→ 네트워크 설정
→ 서비스 배포

이 과정은 몇 주에서 몇 달까지 걸릴 수 있음.

즉 빠르게 확장하기 어렵다.

3) 자원 낭비

기업은 보통 최대 트래픽을 기준으로 서버를 구매한다.

예를 들어 다음 상황을 생각해 보자.

평균 사용자 : 100명
최대 사용자 : 1000명

기업은 최대 사용자 기준으로 서버를 준비해야 한다.

서버 10대 구매

하지만 대부분의 시간에는 사용자 수가 적다.

평균 사용량
→ 서버 2대면 충분

즉

8대 서버 자원 낭비

이 문제는 온프레미스 환경에서 매우 흔하게 발생한다.

1.3 클라우드 컴퓨팅

클라우드는 이러한 문제를 해결하기 위해 등장했다.

클라우드 컴퓨팅은 인터넷을 통해 IT 자원을 제공하는 서비스 모델이다.

기업은 더 이상 서버를 직접 구매하지 않아도 된다.

대신 다음과 같은 방식으로 인프라를 사용할 수 있다.

웹 콘솔 접속
→ 서버 생성
→ 몇 분 후 사용 가능

즉

필요한 인프라를 인터넷을 통해 즉시 사용할 수 있음

대표적인 클라우드 자원

  • 가상 서버
  • 스토리지
  • 네트워크
  • 데이터베이스
  • AI 서비스

이러한 자원을 클라우드 제공자가 대신 운영한다.

대표적인 클라우드 서비스 제공자

  • AWS
  • Microsoft Azure
  • Google Cloud

1.4 클라우드의 핵심 특징

클라우드는 기존 IT 인프라와 다른 특징을 가진다.

대표적인 특징은 다음과 같다.

1) On-demand self service

사용자가 직접 리소스를 생성할 수 있다.

예를 들어 AWS에서는 다음과 같은 작업을 직접 수행할 수 있다.

EC2 서버 생성
S3 저장소 생성
데이터베이스 생성

과거에는 서버를 설치하려면 몇 주가 걸렸지만

클라우드에서는 몇 분 안에 서버 생성 가능.

2) Rapid elasticity

클라우드는 자원을 빠르게 확장하거나 축소할 수 있다.

예를 들어 쇼핑몰 서비스를 생각해 보자.

평소 트래픽
→ 서버 2대

하지만 이벤트 기간에는 사용자 수가 증가한다.

이벤트 기간
→ 서버 20대 필요

클라우드에서는 다음과 같이 확장할 수 있다.

EC2 2대
→ EC2 20대

이 과정은 몇 분 내에 가능하다.

이 특징을 Elasticity (탄력성) 이라고 한다.

3) Measured service

클라우드는 사용한 만큼 비용을 지불한다.

이를 Pay as you go 모델이라고 한다.

예를 들어 EC2 서버를 사용할 경우

1시간 사용
→ 1시간 비용

즉

사용하지 않으면 비용 발생 없음 : 단, EBS 등은 사용하지 않아도 비용 발생됨.

온프레미스 환경에서는 장비를 구매해야 하지만 클라우드에서는 필요할 때만 비용이 발생한다.

1.5 클라우드 서비스 모델

클라우드 서비스는 크게 3가지 모델로 구분한다.

IaaS
PaaS
SaaS

이 세 가지 모델은 사용자가 관리하는 영역이 다르다.

IaaS (Infrastructure as a Service)

클라우드에서 인프라를 제공하는 모델이다.

사용자는 다음 요소를 관리한다.

OS
Middleware
Application

클라우드 제공자는 다음을 관리한다.

물리 서버
네트워크
데이터센터

대표 서비스

  • AWS EC2
  • Azure Virtual Machine

IaaS는 가장 유연한 모델이다.

PaaS (Platform as a Service)

PaaS는 애플리케이션 실행 환경을 제공하는 모델이다.

사용자는 애플리케이션만 개발하면 된다.

예

코드 업로드
→ 자동 배포
→ 서비스 실행

대표 서비스

  • AWS Elastic Beanstalk
  • Google App Engine

개발자는 인프라 관리 부담이 줄어든다.

SaaS (Software as a Service)

SaaS는 완성된 소프트웨어를 제공하는 모델이다.

사용자는 프로그램을 설치할 필요가 없다.

예

  • Microsoft 365
  • Google Docs
  • Salesforce

사용자는 웹 브라우저로 서비스만 사용하면 된다.

1.6 클라우드 배포 모델

클라우드는 배포 방식에 따라 다음과 같이 구분된다.

Public Cloud
Private Cloud
Hybrid Cloud
Multi Cloud

Public Cloud

클라우드 제공자가 인프라를 운영한다.

사용자는 인터넷을 통해 서비스를 사용한다.

대표 서비스

  • AWS
  • Azure
  • Google Cloud

현재 대부분의 기업이 사용하는 방식이다.

Private Cloud

기업이 자체적으로 클라우드 환경을 구축한다.

예

회사 데이터센터
→ OpenStack
→ AWS Outposts

특징

  • 높은 보안
  • 높은 구축 비용

Hybrid Cloud

온프레미스와 클라우드를 함께 사용하는 방식이다.

예

온프레미스 DB
      │
  VPN 또는 DX(전용선)
      │
AWS Web Server

기업은 기존 시스템을 유지하면서 클라우드를 도입할 수 있다.

Multi Cloud

멀티 클라우드(Multi-Cloud)는 AWS, 구글 클라우드, Azure 등 2개 이상의 클라우드 제공업체의 퍼블릭/프라이빗 서비스를 동시에 사용하여 IT 환경을 구성하는 전략이다. 특정 벤더 종속성을 탈피하고, 각 클라우드의 장점을 활용해 비용 효율성, 안정성, 유연성을 극대화하며, 장애 발생 시 리스크를 분산시키는 데 핵심 목적이 있다.
