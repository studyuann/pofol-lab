8장. 컨테이너 로그 관리

docker logs · stdout/stderr · logging driver

8장 학습 목표

  • 컨테이너 로그가 어디에, 어떻게 기록되는지 설명할 수 있다.
  • docker logs 명령의 동작 원리를 이해한다.
  • stdout / stderr 기반 로그 설계의 의미를 이해한다.
  • Docker logging driver의 개념과 역할을 설명할 수 있다.
  • 운영 환경에서 컨테이너 로그 설계 원칙을 말할 수 있다.

8.1 컨테이너 로그의 기본 개념

8.1.1 전통적인 서버 로그 방식

기존 서버 환경에서는 보통 다음과 같은 방식이었다.

  • 애플리케이션이 로그 파일 직접 생성
  • /var/log/*.log 형태로 저장
  • 로그 로테이션(logrotate) 필요
  • 서버 단위 로그 관리

8.1.2 컨테이너 환경에서의 근본적 변화

컨테이너 환경에서는 전제가 달라진다.

  • 컨테이너는 언제든지 삭제/재생성
  • 컨테이너 내부 파일은 영구하지 않음
  • 컨테이너 수가 많아질수록 로그 파일 관리 불가

👉 그래서 컨테이너 환경에서는:

“로그는 파일이 아니라 스트림이다.”

8.2 stdout / stderr 기반 로그 모델

8.2.1 컨테이너 로그의 기본 원칙

컨테이너 애플리케이션은:

  • 표준 출력(stdout)
  • 표준 에러(stderr)

로 로그를 출력해야 한다.

애플리케이션
   ↓
stdout / stderr
   ↓
Docker logging driver
   ↓
docker logs / 외부 로그 시스템

8.2.2 왜 파일 로그를 쓰지 않는가?

컨테이너 내부 파일 로그의 문제점:

  • 컨테이너 삭제 시 로그 소실
  • Volume 연결 없으면 영구 저장 ❌
  • 로그 수집 시스템 연동 어려움

👉 stdout/stderr 로그가 컨테이너 철학에 맞다

8.3 docker logs 명령

8.3.1 기본 사용법

docker logs <컨테이너명>
  • stdout + stderr 출력
  • 컨테이너 내부 파일을 읽는 게 아님
  • Docker 데몬이 수집한 로그를 출력

8.3.2 실시간 로그 확인

docker logs -f <컨테이너명>
  • f : follow
  • tail -f와 유사

8.3.3 로그 범위 제한 (운영에서 매우 중요)

docker logs --tail 100 <컨테이너명>
docker logs --since 10m <컨테이너명>
docker logs --until 2026-02-09T10:00:00 <컨테이너명>

👉 장애 시 로그 범위를 줄이는 능력이 핵심

8.3.4 타임스탬프 포함

docker logs -t <컨테이너명>

8.4 Logging Driver 개념

8.4.1 Logging Driver란?

Docker는 컨테이너 로그를 어디에, 어떤 방식으로 저장할지를 logging driver로 결정한다.

8.4.2 기본 logging driver

json-file
  • 기본값
  • /var/lib/docker/containers/.../*.log
  • docker logs 명령 사용 가능

8.4.3 주요 logging driver 종류

Driver설명docker logs
json-file로컬 JSON 파일⭕
local성능 개선된 로컬⭕
syslogsyslog 서버 전송❌
journaldsystemd journal❌
fluentd로그 수집기 연동❌
awslogsCloudWatch Logs❌

👉 logging driver에 따라

docker logs 사용 가능 여부가 달라진다

8.5 Logging Driver 확인 및 설정

8.5.1 현재 설정 확인

docker info | grep -i logging

8.5.2 컨테이너별 logging driver 지정

docker run -d \
  --log-driver=json-file \
  nginx

8.5.3 로그 옵션 설정

--log-opt max-size=10m
--log-opt max-file=3

👉 로그 무한 증가 방지 (필수)

8.6 로그 로테이션 (중요)

8.6.1 왜 필요한가?

  • json-file 로그는 계속 누적
  • 디스크 고갈 위험

8.6.2 json-file 로테이션 설정 예

docker run -d \
  --log-driver=json-file \
  --log-opt max-size=10m \
  --log-opt max-file=5 \
  nginx

8.6.3 데몬 전체 설정 (운영 표준)

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "5"
  }
}

경로:

/etc/docker/daemon.json

👉 운영 서버에서는 반드시 설정

8.7 컨테이너 로그 설계 원칙 (운영 관점)

원칙 1

  • 애플리케이션은 stdout/stderr로만 로그 출력

원칙 2

  • 컨테이너 내부에 로그 파일 생성 ❌

원칙 3

  • 로그 수집은 Docker 외부 시스템에서 수행
    • ELK
    • Fluentd
    • CloudWatch Logs 등

원칙 4

  • docker logs는 운영자가 즉시 확인하는 1차 도구

8.8 운영 장애 분석 흐름

  1. docker ps → 문제 컨테이너 확인
  1. docker logs --tail 100 → 최근 로그
  1. docker logs --since 5m → 장애 구간
  1. 필요 시 logging system 연동

8장 핵심 정리

  • 컨테이너 로그는 stdout/stderr 스트림
  • docker logs는 파일을 읽는 게 아니다
  • logging driver에 따라 동작 방식 달라짐
  • 운영 서버에서는 로그 로테이션 필수
  • 로그는 “남기는 것”보다 “버리는 것”이 더 중요
