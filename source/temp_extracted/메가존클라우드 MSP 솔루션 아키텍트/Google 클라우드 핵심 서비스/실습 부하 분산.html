실습. 부하 분산

주제

Managed Instance Group(MIG)과 Autoscaler를 이용한 HTTP Load Balancer 구축

1. 실습 개요

이 실습은 여러 VM 인스턴스에 웹 서비스를 배포하고, GCP의 HTTP Load Balancer를 이용해 트래픽을 분산하는 과정으로 구성함.

또한 Managed Instance Group과 Autoscaler를 함께 사용하여, 트래픽 증가 시 인스턴스 수가 자동으로 확장되고 감소 시 자동으로 축소되는 구조를 확인함.

이 실습을 통해 다음 내용을 익히는 것을 목표로 함.

  • 인스턴스 템플릿 생성 방법 이해
  • Managed Instance Group 생성 방법 이해
  • Autoscaler 설정 방법 이해
  • Health Check 생성 및 연결 방법 이해
  • HTTP Load Balancer 생성 방법 이해
  • 부하 발생 시 인스턴스 수가 자동으로 증가하는 동작 확인
  • 부하 감소 시 인스턴스 수가 자동으로 감소하는 동작 확인

2. 실습 목표

실습 완료 후 학습자는 다음을 수행할 수 있어야 함.

  • 동일한 설정의 웹 서버 인스턴스를 템플릿 기반으로 배포할 수 있음
  • MIG를 이용하여 최소 2대, 최대 4대의 인스턴스를 자동 관리할 수 있음
  • Health Check를 이용하여 정상 동작 중인 백엔드만 서비스에 포함시킬 수 있음
  • HTTP Load Balancer를 이용하여 클라이언트 요청을 여러 인스턴스로 분산할 수 있음
  • Autoscaler가 CPU 사용률 기준으로 스케일 아웃/스케일 인하는 과정을 확인할 수 있음

3. 실습 환경

사용 서비스

  • Google Compute Engine
  • Instance Template
  • Managed Instance Group
  • Autoscaler
  • Health Check
  • HTTP Load Balancer
  • Firewall Rule

실습 조건

  • 최소 인스턴스 수: 2
  • 최대 인스턴스 수: 4
  • 웹 서버 포트: 80
  • Health Check 방식: HTTP
  • Autoscaling 기준: CPU 사용률 60%

권장 리전

  • asia-northeast3(서울) 또는 수업 환경에 맞는 리전 사용

4. 실습 아키텍처

구성은 아래와 같음.

  1. 인스턴스 템플릿을 생성함
  1. 템플릿을 기반으로 Managed Instance Group을 생성함
  1. 그룹의 초기 인스턴스 수를 2대로 설정함
  1. Autoscaler를 설정하여 최소 2대, 최대 4대로 자동 확장 가능하도록 구성함
  1. Health Check를 생성하여 백엔드 상태를 점검함
  1. HTTP Load Balancer를 생성하고 백엔드로 MIG를 연결함
  1. 외부에서 접속하여 요청이 여러 VM으로 분산되는지 확인함
  1. 부하 도구를 사용해 CPU 사용률을 높이고 인스턴스 수가 늘어나는지 확인함

5. 사전 준비

실습 전에 아래 사항을 확인해야 함.

  • 프로젝트가 생성되어 있어야 함
  • Compute Engine API가 활성화되어 있어야 함
  • 결제가 연결되어 있어야 함
  • 실습 계정에 다음 권한이 있어야 함
    • Compute Admin
    • Network Admin
    • Load Balancer Admin 정도가 있으면 실습이 수월함

6. 핵심 개념 설명

6.1 Managed Instance Group(MIG)

MIG는 동일한 설정을 가진 VM 인스턴스를 여러 대 묶어서 관리하는 기능임.

한 대씩 수동으로 서버를 만들지 않고, 템플릿을 기준으로 같은 사양의 VM을 자동으로 여러 대 생성함.

MIG의 장점은 다음과 같음.

  • 동일한 웹 서버를 여러 대 쉽게 생성 가능
  • 장애가 발생한 인스턴스를 자동으로 복구 가능
  • 로드밸런서 백엔드로 쉽게 연결 가능
  • Autoscaler와 결합하여 자동 확장 가능

6.2 Autoscaler

Autoscaler는 인스턴스 수를 자동으로 조절하는 기능임.

예를 들어 CPU 사용률이 높아지면 서버를 늘리고, 낮아지면 서버 수를 줄임.

이번 실습에서는 다음 기준을 사용함.

  • 최소: 2대
  • 최대: 4대
  • CPU 사용률 목표: 60%

즉, 서버 2대로 시작하지만 트래픽이 증가하여 CPU가 기준치를 넘으면 3대, 4대까지 자동으로 늘어날 수 있음.

6.3 Health Check

Health Check는 백엔드 인스턴스가 정상 동작 중인지 검사하는 기능임.

웹 서버가 살아 있는지, 특정 포트가 응답하는지, 특정 URL이 정상 응답하는지 확인함.

로드밸런서는 Health Check 결과를 바탕으로 정상 인스턴스에만 트래픽을 전달함.

6.4 Load Balancer

Load Balancer는 클라이언트 요청을 여러 서버에 나누어 전달하는 장치임.

하나의 서버에만 요청이 집중되지 않도록 분산하여 서비스 안정성과 확장성을 높임.

7. 실습 절차

7-1. VPC 방화벽 규칙 생성

웹 접속과 Health Check가 가능하도록 방화벽을 허용해야 함.

콘솔에서 수행

  • VPC 네트워크 → 방화벽 → 방화벽 규칙 만들기
  • 이름: allow-http
  • 대상: 네트워크의 모든 인스턴스 또는 태그 지정
  • 소스 IPv4 범위: 0.0.0.0/0
  • 프로토콜/포트: tcp:80

Health Check용도 별도로 허용하는 것이 좋음.

Google Load Balancer Health Check는 Google이 사용하는 점검 IP 대역에서 들어옴.

실습 단순화를 위해 웹 태그에 대해 허용 규칙을 하나 더 만드는 방식이 좋음.

예시:

  • 이름: allow-health-check
  • 소스 IPv4 범위: 130.211.0.0/22, 35.191.0.0/16
  • 프로토콜/포트: tcp:80

gcloud 명령

gcloud compute firewall-rules create allow-http \
  --allow tcp:80 \
  --source-ranges=0.0.0.0/0 \
  --target-tags=http-server

gcloud compute firewall-rules create allow-health-check \
  --allow tcp:80 \
  --source-ranges=130.211.0.0/22,35.191.0.0/16 \
  --target-tags=http-server

명령 설명

  • firewall-rules create

    새로운 방화벽 규칙을 생성하는 명령임

  • -allow tcp:80

    TCP 80번 포트를 허용함. 즉 HTTP 접속을 허용함

  • -source-ranges

    접속을 허용할 출발지 IP 대역을 지정함

  • -target-tags=http-server

    http-server 네트워크 태그가 붙은 인스턴스에만 규칙이 적용됨

7-2. 인스턴스 템플릿 생성

웹 서버가 자동 설치되도록 시작 스크립트를 포함한 템플릿을 생성함.

시작 스크립트 예시

이 스크립트는 Apache 웹 서버를 설치하고, 현재 호스트 이름을 웹 페이지에 출력함.

로드밸런싱 결과를 확인할 때 어떤 인스턴스가 응답했는지 쉽게 볼 수 있음.

#!/bin/bash
apt-get update
apt-get install -y apache2

HOSTNAME=$(hostname)

cat <<EOF > /var/www/html/index.html
<html>
  <head><title>GCP Load Balancing Lab</title></head>
  <body>
    <h1>Load Balancing Test</h1>
    <p>Served by: ${HOSTNAME}</p>
  </body>
</html>
EOF

systemctl enable apache2
systemctl restart apache2

gcloud 명령

gcloud compute instance-templates create web-template \
  --machine-type=e2-micro \
  --image-family=debian-12 \
  --image-project=debian-cloud \
  --tags=http-server \
  --metadata-from-file startup-script=startup.sh

명령 설명

  • instance-templates create web-template

    web-template이라는 이름의 인스턴스 템플릿을 생성함

  • -machine-type=e2-micro

    VM 사양을 지정함. 실습용으로 비용이 적은 타입임

  • -image-family=debian-12

    Debian 12 계열 이미지를 사용함

  • -image-project=debian-cloud

    이미지를 제공하는 프로젝트를 지정함

  • -tags=http-server

    앞에서 만든 방화벽 규칙이 적용되도록 태그를 지정함

  • -metadata-from-file startup-script=startup.sh

    VM이 처음 부팅될 때 실행할 스크립트 파일을 연결함

7-3. Managed Instance Group 생성

초기 인스턴스 수를 2대로 생성함.

gcloud 명령

gcloud compute instance-groups managed create web-mig \
  --base-instance-name=web \
  --size=2 \
  --template=web-template \
  --zone=asia-northeast3-a

명령 설명

  • instance-groups managed create web-mig

    관리형 인스턴스 그룹을 생성함

  • -base-instance-name=web

    생성되는 VM 이름의 기본 접두사를 지정함

    예를 들어 web-xxxx 형태의 이름이 생성됨

  • -size=2

    초기 인스턴스 수를 2대로 설정함

  • -template=web-template

    앞에서 만든 템플릿을 기반으로 인스턴스를 생성함

  • -zone=asia-northeast3-a

    그룹이 생성될 존을 지정함

확인 명령

gcloud compute instance-groups managed list-instances web-mig \
  --zone=asia-northeast3-a

이 명령은 MIG 안에 실제로 어떤 인스턴스가 생성되었는지 확인할 때 사용함.

7-4. Health Check 생성

로드밸런서가 백엔드 웹 서버 상태를 점검할 수 있도록 HTTP Health Check를 생성함.

gcloud 명령

gcloud compute health-checks create http web-hc \
  --port 80 \
  --request-path /

명령 설명

  • health-checks create http web-hc

    HTTP 타입의 Health Check를 생성함

  • -port 80

    80번 포트로 접속하여 상태를 확인함

  • -request-path /

    루트 경로 /에 요청을 보내 정상 응답 여부를 점검함

이 설정은 웹 서버가 HTTP 80 포트에서 동작하고, / 요청에 정상 응답할 때 healthy 상태로 판단하도록 함.

7-5. Autoscaler 설정

최소 2대, 최대 4대 범위에서 CPU 사용률을 기준으로 자동 확장하도록 설정함.

gcloud 명령

gcloud compute instance-groups managed set-autoscaling web-mig \
  --zone=asia-northeast3-a \
  --min-num-replicas=2 \
  --max-num-replicas=4 \
  --target-cpu-utilization=0.6 \
  --cool-down-period=90

명령 설명

  • set-autoscaling

    MIG에 Autoscaler 정책을 연결함

  • -min-num-replicas=2

    인스턴스 수가 2대 아래로 내려가지 않도록 설정함

  • -max-num-replicas=4

    인스턴스 수가 최대 4대까지만 증가하도록 제한함

  • -target-cpu-utilization=0.6

    평균 CPU 사용률 목표를 60%로 설정함

    이 값을 넘는 상태가 계속되면 스케일 아웃 가능성이 높아짐

  • -cool-down-period=90

    새 인스턴스가 생성된 뒤 안정화될 시간을 90초로 둠

    너무 빠르게 확장/축소 판단하지 않도록 완충 역할을 함

7-6. 백엔드 서비스 생성

Load Balancer가 실제 트래픽을 전달할 백엔드 서비스를 생성함.

gcloud compute backend-services create web-backend-service \
  --protocol=HTTP \
  --port-name=http \
  --health-checks=web-hc \
  --global

명령 설명

  • backend-services create

    로드밸런서용 백엔드 서비스를 생성함

  • -protocol=HTTP

    백엔드와 HTTP 방식으로 통신함

  • -port-name=http

    MIG의 named port와 일치시켜야 함

  • -health-checks=web-hc

    어떤 Health Check를 사용할지 지정함

  • -global

    글로벌 HTTP(S) 로드밸런서용 리소스로 생성함

7-7. MIG에 named port 설정

백엔드 서비스가 MIG의 어느 포트를 사용할지 알 수 있도록 named port를 지정함.

gcloud compute instance-groups managed set-named-ports web-mig \
  --named-ports=http:80 \
  --zone=asia-northeast3-a

명령 설명

  • set-named-ports

    인스턴스 그룹 포트에 이름을 붙이는 기능임

  • http:80

    http라는 이름이 실제 80번 포트를 가리키도록 설정함

이 설정은 백엔드 서비스 생성 시 지정했던 --port-name=http 와 연결됨.

7-8. 백엔드 서비스에 MIG 추가

gcloud compute backend-services add-backend web-backend-service \
  --instance-group=web-mig \
  --instance-group-zone=asia-northeast3-a \
  --global

명령 설명

  • add-backend

    백엔드 서비스에 실제 인스턴스 그룹을 연결함

  • -instance-group=web-mig

    연결할 MIG 이름을 지정함

  • -instance-group-zone=asia-northeast3-a

    MIG가 위치한 존을 지정함

7-9. URL 맵 생성

클라이언트 요청 URL을 어떤 백엔드 서비스로 보낼지 정의함.

gcloud compute url-maps create web-map \
  --default-service=web-backend-service

명령 설명

  • url-maps create web-map

    URL 맵을 생성함

  • -default-service=web-backend-service

    기본 요청은 모두 이 백엔드 서비스로 전달되도록 설정함

7-10. HTTP 프록시 생성

gcloud compute target-http-proxies create web-proxy \
  --url-map=web-map

명령 설명

  • target-http-proxies create

    HTTP 요청을 받아 URL 맵 규칙에 따라 전달하는 프록시를 생성함

  • -url-map=web-map

    앞에서 만든 URL 맵을 연결함

7-11. 글로벌 포워딩 룰 생성

외부 IP를 할당하고 80번 포트 요청을 HTTP 프록시로 전달함.

gcloud compute forwarding-rules create web-forwarding-rule \
  --global \
  --target-http-proxy=web-proxy \
  --ports=80

명령 설명

  • forwarding-rules create

    외부에서 들어오는 요청을 어떤 대상에게 보낼지 지정하는 규칙임

  • -global

    글로벌 HTTP 로드밸런서로 설정함

  • -target-http-proxy=web-proxy

    요청을 HTTP 프록시로 전달함

  • -ports=80

    80번 포트 요청을 받음

7-12. 외부 IP 확인

gcloud compute forwarding-rules list

또는 특정 규칙 조회:

gcloud compute forwarding-rules describe web-forwarding-rule \
  --global

여기서 외부 IP를 확인한 뒤 브라우저에서 접속함.

예:

http://EXTERNAL_IP

페이지를 여러 번 새로고침하면 응답 인스턴스 이름이 바뀌는 것을 볼 수 있음.

다만 세션 유지나 캐시 영향으로 계속 같은 인스턴스처럼 보일 수도 있으므로, 시크릿 창이나 여러 요청 도구를 함께 사용하면 확인이 쉬움.

8. 부하 테스트

Autoscaler가 동작하는지 확인하려면 CPU 부하를 발생시켜야 함.

가장 단순한 방법은 MIG에 속한 인스턴스 중 하나에 접속하여 CPU를 사용하는 프로세스를 실행하는 것임.

다만 실제 수업에서는 여러 클라이언트 요청만으로는 CPU가 충분히 오르지 않을 수 있으므로, CPU stress 도구를 사용하는 것이 더 확실함.

인스턴스 접속

gcloud compute ssh INSTANCE_NAME --zone=asia-northeast3-a

stress 설치 및 실행

sudo apt-get update
sudo apt-get install -y stress
stress --cpu 2 --timeout 300

명령 설명

  • stress --cpu 2 --timeout 300

    CPU 2개를 300초 동안 강하게 사용하도록 부하를 발생시킴

이 작업을 여러 인스턴스에서 수행하거나, 애플리케이션 요청량을 증가시키면 MIG 평균 CPU가 올라갈 수 있음.

인스턴스 수 확인

gcloud compute instance-groups managed list-instances web-mig \
  --zone=asia-northeast3-a

또는 Autoscaler 상태 조회:

gcloud compute instance-groups managed describe web-mig \
  --zone=asia-northeast3-a

CPU 사용률이 목표치를 일정 시간 초과하면 인스턴스 수가 3대, 4대로 증가할 수 있음.

9. 예상 결과

정상적으로 구성되었다면 다음 결과가 보여야 함.

  • 처음에는 인스턴스가 2대 생성되어 있음
  • 브라우저에서 Load Balancer IP로 접속 가능함
  • 웹 페이지에 인스턴스 이름이 표시됨
  • 여러 요청 시 서로 다른 인스턴스가 응답할 수 있음
  • CPU 부하를 높이면 Autoscaler가 인스턴스를 추가 생성함
  • 최대 4대까지만 증가함
  • 부하가 감소하면 일정 시간 후 다시 2대 수준으로 줄어듦

10. 정리 명령

실습이 끝난 뒤 비용 방지를 위해 리소스를 삭제해야 함.

gcloud compute forwarding-rules delete web-forwarding-rule --global
gcloud compute target-http-proxies delete web-proxy
gcloud compute url-maps delete web-map
gcloud compute backend-services delete web-backend-service --global
gcloud compute health-checks delete web-hc
gcloud compute instance-groups managed delete web-mig --zone=asia-northeast3-a
gcloud compute instance-templates delete web-template
gcloud compute firewall-rules delete allow-http
gcloud compute firewall-rules delete allow-health-check
