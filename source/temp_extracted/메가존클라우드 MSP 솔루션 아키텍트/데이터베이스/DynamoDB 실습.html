실습 1. DynamoDB 테이블 생성

1) 목표

  • DynamoDB 테이블 구조 이해
  • Partition Key / Sort Key 개념 습득

2) 시나리오

사용자 주문 정보를 저장하는 테이블 생성

3) 테이블 설계

항목값
테이블 이름Orders
Partition KeyuserId (String)
Sort KeyorderId (String)
Billing ModeOn-Demand

4) 실습 단계

  1. AWS Console → DynamoDB → Tables
  1. Create table
  1. 설정
    • Table name: Orders
    • Partition key: userId (String)
    • Sort key: orderId (String)
  1. Billing mode: On-Demand
  1. Create table

>> 확인 포인트

  • 테이블 상태가 Active
  • Primary key 구조 확인

  1. Orders 테이블 클릭

  1. Create item

{

➕ 추가 아이템

{
  "userId": "user-001",
  "orderId": "order-002",
  "product": "Mouse",
  "price": 30000,
  "orderDate": "2026-01-02",
  "status": "SHIPPED"

{
  "userId": "user-002",
  "orderId": "order-001",
  "product": "Monitor",
  "price": 250000,

  • 서로 다른 userId는 다른 파티션

실습 3. GetItem vs Query

- 목표

  • 단건 조회와 조건 조회 차이 이해

1) GetItem (기본 키 전체 필요)

  1. Explore table items
  1. Partition key: user-001
  1. Sort key: order-001
  1. Get item

📌 특징

  • 빠름
  • 정확한 키 값 필요

2) Query (Partition Key 기준)

  1. Query 탭 선택
  1. Partition key = user-001
  1. 실행

📌 특징

  • 동일 사용자 주문 전체 조회
  • 실무에서 가장 많이 사용

>> 확인 포인트

  • Query는 Partition Key 필수
  • Scan보다 훨씬 빠름

실습 5. GSI (Global Secondary Index) 생성

1) 목표

  • 기본 키 외 조회 패턴 해결

2) 요구사항

주문 상태(status)로 주문 조회

3) GSI 생성

  1. Orders 테이블 → Indexes
  1. Create index
  1. 설정
    • Index name: status-index
    • Partition key: status (String)
    • Sort key: orderDate (String)
    • Projection: All

>> 확인 포인트

  • GSI 생성 완료 상태
  • 별도 용량 관리 없음 (On-Demand)

실습 6. GSI Query

1) 목표

  • GSI 기반 조회 수행

2) 실습 단계

  1. Explore table items
  1. Index 선택: status-index
  1. Partition key = PAID
  1. Query 실행

3) 확인 포인트

  • PAID 상태 주문만 조회
  • 기본 테이블 키 없이도 조회 가능

실습 8. TTL(Time To Live)

1) 목표

  • 자동 데이터 삭제 기능 이해

2) TTL 설정

  1. Table settings → TTL
  1. Attribute name: expireAt
  1. Enable TTL

3) 아이템 수정

"expireAt": 1767225600

(Unix Timestamp)

>> 확인 포인트

  • 지정 시간 이후 자동 삭제
  • 로그 / 세션 데이터에 유용

>> 핵심 정리
