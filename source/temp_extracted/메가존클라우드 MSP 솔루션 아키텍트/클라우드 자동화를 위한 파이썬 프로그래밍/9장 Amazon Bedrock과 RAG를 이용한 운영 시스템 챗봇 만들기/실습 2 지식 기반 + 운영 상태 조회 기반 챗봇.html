실습 2. 지식 기반 + 운영 상태 조회 기반 챗봇

1. 실습 개요

이 실습에서는 Amazon Bedrock Agent를 사용해 정적 문서 검색과 실시간 인프라 상태 조회를 함께 수행하는 지능형 운영 챗봇을 구현한다.

실습 1에서 만든 RAG 기반 지식 서비스는 매뉴얼, 장애 대응 문서, 패치 일정 문서처럼 이미 저장된 문서를 기반으로 답변한다.

하지만 운영 환경에서는 문서만으로 답할 수 없는 질문이 많다.

예를 들어 다음 질문을 보자.

지금 test-svr 인스턴스 상태는 어때?

이 질문은 매뉴얼 문서에 답이 들어 있지 않다.

현재 EC2 상태를 AWS API로 조회해야 답할 수 있다.

반대로 다음 질문은 실시간 API 조회가 아니라 문서 검색이 더 적합하다.

정기 패치 일자는 언제야?

이 질문은 운영 매뉴얼이나 패치 정책 문서에 들어 있는 정보를 검색해야 한다.

따라서 이번 실습에서는 Bedrock Agent가 질문의 성격을 판단해 다음처럼 동작하게 만든다.

사용자 질문
   ↓
Bedrock Agent
   ↓
질문 의도 판단
   ├─ 실시간 EC2 상태 질문 → Lambda 도구 호출
   └─ 매뉴얼/패치/장애 대응 질문 → Knowledge Base 검색
   ↓
최종 답변 생성

Amazon Bedrock Agents는 Foundation Model, 데이터 소스, 소프트웨어 애플리케이션, 사용자 대화를 오케스트레이션하고, 필요한 경우 API 호출과 Knowledge Base 조회를 수행할 수 있다.

2. 실습 목표

이 실습을 완료하면 다음을 수행할 수 있다.

  • Bedrock Agent의 역할을 설명할 수 있다.
  • Agent가 Lambda 함수를 도구처럼 호출하는 구조를 이해할 수 있다.
  • Lambda에서 boto3를 사용해 EC2 상태를 조회할 수 있다.
  • Agent Action Group을 구성할 수 있다.
  • Knowledge Base를 Agent에 연결할 수 있다.
  • 하나의 질문 안에서 실시간 운영 상태와 매뉴얼 정보를 함께 답변하게 만들 수 있다.
  • Lambda 실행 역할과 Lambda 리소스 기반 정책의 차이를 설명할 수 있다.

3. 이번 실습에서 만드는 결과물

6. 핵심 개념 설명

6.1 Bedrock Agent란 무엇인가

Bedrock Agent는 사용자의 질문을 단순히 LLM에 전달하는 역할만 하지 않는다.

Agent는 사용자의 질문을 분석한 뒤, 필요한 작업을 스스로 선택한다.

예를 들어 사용자가 다음처럼 질문했다고 하자.

지금 test-svr 상태는 어떻고, 정기 패치 일자는 언제야?

이 질문에는 두 가지 의도가 섞여 있다.

첫 번째는 현재 EC2 상태 조회이다.

지금 test-svr 상태는 어때?

이 질문은 실시간 AWS API 조회가 필요하다.

두 번째는 매뉴얼 검색이다.

정기 패치 일자는 언제야?

이 질문은 Knowledge Base 검색이 필요하다.

Agent는 이 두 작업을 분리해서 처리하고, 마지막에 하나의 답변으로 합친다.

6.2 Action Group이란 무엇인가

Action Group은 Agent가 호출할 수 있는 작업 묶음이다.

예를 들어 이번 실습에서는 다음 작업을 Action Group으로 만든다.

get_ec2_status

이 작업은 EC2 인스턴스 이름을 입력받고, 현재 상태를 반환한다.

Agent는 사용자가 “test-svr 상태 알려줘”라고 질문하면 get_ec2_status 기능이 필요하다고 판단하고 Lambda 함수를 호출한다.

Bedrock Agent의 Action Group은 Lambda 함수와 연결될 수 있으며, Agent는 API 스키마 또는 Function details에 정의된 정보를 바탕으로 필요한 입력값을 Lambda로 전달한다.

6.3 Lambda의 역할

Lambda는 실제 AWS API를 호출하는 실행 코드이다.

이번 실습에서 Lambda는 다음 작업을 수행한다.

1. Agent로부터 instance_name 값을 받음
2. EC2 describe_instances API 호출
3. Name 태그가 instance_name과 같은 인스턴스 검색
4. 인스턴스 ID, 이름, 상태, 타입, Private IP 조회
5. 결과를 Agent가 이해할 수 있는 JSON 형식으로 반환

6.4 Knowledge Base의 역할

Knowledge Base는 운영 매뉴얼, 패치 일정, 장애 대응 절차 같은 문서를 검색하는 역할을 한다.

이번 실습에서는 실습 1에서 만든 Knowledge Base를 Agent에 연결한다.

사용자가 다음처럼 질문하면 Knowledge Base가 사용된다.

정기 패치 일자는 언제야?
장애 발생 시 1차 조치 절차는 뭐야?
서버 점검 전 확인해야 하는 항목은 뭐야?

7.2 Lambda 코드 작성

Lambda 코드 편집기에 아래 코드를 입력한다.

파일명 개념상 lambda_function.py이다.

import json
import boto3
from botocore.exceptions import ClientError

ec2 = boto3.client("ec2")

def get_parameter(event, name, default=None):
    """
    Bedrock Agent가 Lambda로 전달한 parameters 목록에서
    특정 이름의 값을 찾아 반환한다.
    """
    parameters = event.get("parameters", [])

    for parameter in parameters:
        if parameter.get("name") == name:
            return parameter.get("value")

    return default

def find_instances_by_name(instance_name):
    """
    EC2 Name 태그를 기준으로 인스턴스를 조회한다.
    terminated 인스턴스는 이미 삭제된 인스턴스이므로 운영 상태 조회 결과에 포함하지 않는다.
    """
    response = ec2.describe_instances(
        Filters=[
            {
                "Name": "tag:Name",
                "Values": [instance_name]
            },
            {
                "Name": "instance-state-name",
                "Values": ["pending", "running", "stopping", "stopped"]
            }
        ]
    )

    instances = []

    for reservation in response.get("Reservations", []):
        for instance in reservation.get("Instances", []):
            name = ""

            for tag in instance.get("Tags", []):
                if tag.get("Key") == "Name":
                    name = tag.get("Value")
                    break

            instances.append({
                "instance_id": instance.get("InstanceId"),
                "name": name,
                "state": instance.get("State", {}).get("Name"),
                "instance_type": instance.get("InstanceType"),
                "private_ip": instance.get("PrivateIpAddress", "N/A"),
                "public_ip": instance.get("PublicIpAddress", "N/A"),
                "availability_zone": instance.get("Placement", {}).get("AvailabilityZone")
            })

    return instances

def build_agent_response(event, response_body):
    """
    Bedrock Agent가 이해할 수 있는 응답 형식으로 결과를 반환한다.
    """
    return {
        "messageVersion": "1.0",
        "response": {
            "actionGroup": event.get("actionGroup"),
            "function": event.get("function"),
            "functionResponse": {
                "responseBody": {
                    "TEXT": {
                        "body": json.dumps(response_body, ensure_ascii=False)
                    }
                }
            }
        },
        "sessionAttributes": event.get("sessionAttributes", {}),
        "promptSessionAttributes": event.get("promptSessionAttributes", {})
    }

def lambda_handler(event, context):
    """
    Lambda 진입점: EC2 인스턴스 조회 후 Agent 응답 형식으로 반환한다.
    """
    print("Received event:")
    print(json.dumps(event, ensure_ascii=False))

    try:
        instance_name = get_parameter(event, "instance_name")

        if not instance_name:
            response_body = {
                "success": False,
                "message": "instance_name 파라미터가 필요함"
            }
            return build_agent_response(event, response_body)

        instances = find_instances_by_name(instance_name)

        if not instances:
            response_body = {
                "success": True,
                "message": f"{instance_name} 이름을 가진 EC2 인스턴스를 찾을 수 없음",
                "instances": []
            }
            return build_agent_response(event, response_body)

        response_body = {
            "success": True,
            "message": f"{instance_name} 인스턴스 상태 조회 완료",
            "instances": instances
        }

        return build_agent_response(event, response_body)

    except ClientError as e:
        response_body = {
            "success": False,
            "message": "AWS API 호출 중 오류 발생",
            "error": str(e)
        }
        return build_agent_response(event, response_body)

    except Exception as e:
        response_body = {
            "success": False,
            "message": "Lambda 처리 중 알 수 없는 오류 발생",
            "error": str(e)
        }
        return build_agent_response(event, response_body)

8. Step 2. Lambda 실행 역할에 EC2 조회 권한 추가

Lambda 함수는 기본적으로 EC2를 조회할 권한이 없다.

따라서 Lambda 실행 역할에 EC2 읽기 권한을 추가해야 한다.

8.1 Lambda 실행 역할 이름 확인

Lambda 콘솔에서 확인한다.

Lambda
→ rag-lab
→ Configuration
→ Permissions
→ Execution role

Role name을 확인한다.

예시는 다음과 같다.

rag-lab-role-abc123

8.2 CLI로 권한 추가

아래 명령에서 [함수_역할_이름] 부분을 실제 역할 이름으로 바꾼다.

aws iam attach-role-policy \
--role-name [함수_역할_이름] \
--policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess

예시는 다음과 같다.

aws iam attach-role-policy \
--role-name rag-lab-role-abc123 \
--policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess

8.3 명령어 설명

aws iam attach-role-policy

IAM 역할에 관리형 정책을 연결하는 명령이다.

--role-name rag-lab-role-abc123

정책을 연결할 IAM 역할 이름이다.

여기서는 Lambda 함수가 사용하는 실행 역할을 입력한다.

--policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess

AWS 관리형 정책 중 EC2 읽기 전용 권한을 부여한다.

이 권한이 있어야 Lambda 코드에서 다음 API를 호출할 수 있다.

ec2.describe_instances()

9.3 자주 발생하는 오류

오류 1. AccessDenied

예시는 다음과 같다.

An error occurred (UnauthorizedOperation) when calling the DescribeInstances operation

원인은 Lambda 실행 역할에 EC2 조회 권한이 없기 때문이다.

해결 방법은 다음 명령을 다시 확인한다.

aws iam attach-role-policy \
--role-name [함수_역할_이름] \
--policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess

오류 2. 인스턴스를 찾을 수 없음

예시는 다음과 같다.

{
  "success":true,
  "message":"test-svr 이름을 가진 EC2 인스턴스를 찾을 수 없음",
  "instances": []
}

원인은 보통 다음 중 하나이다.

  • EC2 인스턴스의 Name 태그가 test-svr가 아님
  • Lambda와 EC2 인스턴스의 리전이 다름
  • 인스턴스가 terminated 상태임

10.1 Agent 생성

→ Create Agent

Agent 이름은 다음처럼 입력한다.

설명은 다음처럼 입력한다.

EC2 실시간 상태 조회와 운영 매뉴얼 검색을 함께 수행하는 인프라 운영 챗봇

AWS 문서 기준으로 Agent를 Prepare하고 테스트하려면 Agent resource role, Foundation Model, Instructions 구성이 필요하고, Action Group 또는 Knowledge Base를 하나 이상 구성하는 것이 일반적이다.

10.3 Agent 지침 입력

Instructions에 아래 내용을 입력한다.

너는 클라우드 인프라 운영 전문가이다.

사용자의 질문을 분석해서 실시간 운영 상태 조회가 필요한지, 운영 매뉴얼 검색이 필요한지 판단한다.

다음 규칙을 따른다.

1. EC2 인스턴스의 현재 상태, 실행 여부, 중지 여부, 서버 상태, 지금 상태를 묻는 질문은 get_ec2_status 함수를 사용한다.
2. get_ec2_status 함수를 사용할 때는 사용자가 말한 서버 이름을 instance_name 파라미터로 전달한다.
3. 정기 패치 일정, 장애 대응 절차, 운영 정책, 점검 항목, 매뉴얼 내용은 Knowledge Base를 사용해 검색한다.
4. 하나의 질문에 실시간 상태 조회와 매뉴얼 검색이 함께 포함되어 있으면 두 작업을 모두 수행한 뒤 하나의 답변으로 정리한다.
5. Lambda 함수 결과에 state 값이 있으면 running, stopped, pending, stopping 상태를 사용자가 이해하기 쉽게 설명한다.
6. 모르는 내용은 추측하지 말고 확인 가능한 정보 기준으로 답변한다.
7. 답변은 한국어로 작성한다.

  • 어떤 값을 입력해야 하는지
  • 예시 값은 무엇인지
  • 언제 이 함수를 사용해야 하는지

13. Step 7. Agent가 Lambda를 호출할 수 있도록 권한 추가

여기서 중요한 권한이 하나 더 필요하다.

앞에서 추가한 권한은 Lambda가 EC2를 조회할 수 있는 권한이었다.

이번에 추가할 권한은 Bedrock Agent가 Lambda를 실행할 수 있는 권한이다.

두 권한은 다르다.

권한대상목적
Lambda 실행 역할 권한Lambda → EC2Lambda가 EC2 API를 호출
Lambda 리소스 기반 정책Bedrock Agent → LambdaAgent가 Lambda 함수를 실행

AWS는 Bedrock Agent가 Lambda를 호출하려면 Lambda 함수에 리소스 기반 정책을 추가해야 한다고 안내한다.

13.1 Agent ID 확인

Bedrock Agent 상세 화면에서 Agent ID를 확인한다.

예시는 다음과 같다.

ABCDEFGHIJ

13.2 AWS 계정 ID 확인

CLI에서 다음 명령을 실행한다.

aws sts get-caller-identity \
--query Account \
--output text

예상 출력은 다음과 같다.

123456789012

13.3 Lambda add-permission 실행

아래 명령에서 값을 수정한다.

aws lambda add-permission \
--function-name rag-lab \
--statement-id allow-bedrock-agent-invoke \
--action"lambda:InvokeFunction" \
--principal bedrock.amazonaws.com \
--source-arn"arn:aws:bedrock:ap-northeast-2:[계정ID]:agent/[에이전트ID]"

예시는 다음과 같다.

aws lambda add-permission \
--function-name rag-lab \
--statement-id allow-bedrock-agent-invoke \
--action"lambda:InvokeFunction" \
--principal bedrock.amazonaws.com \
--source-arn"arn:aws:bedrock:ap-northeast-2:123456789012:agent/ABCDEFGHIJ"

13.4 명령어 설명

aws lambda add-permission

Lambda 함수에 리소스 기반 권한을 추가한다.

--function-name rag-lab

권한을 추가할 Lambda 함수 이름이다.

--statement-id allow-bedrock-agent-invoke

정책 문장 ID이다.

동일한 statement ID를 다시 사용하면 오류가 발생할 수 있다.

이미 추가했다면 다른 ID를 사용하거나 기존 정책을 제거해야 한다.

--action"lambda:InvokeFunction"

Lambda 함수를 호출할 수 있는 권한이다.

--principal bedrock.amazonaws.com

Bedrock 서비스가 Lambda를 호출할 수 있도록 허용한다.

--source-arn"arn:aws:bedrock:ap-northeast-2:123456789012:agent/ABCDEFGHIJ"

특정 Bedrock Agent만 이 Lambda를 호출할 수 있도록 제한한다.

AWS 권장 방식에서는 SourceAccount와 SourceArn 조건을 사용해 신뢰할 수 있는 Bedrock Agent만 Lambda를 호출하게 제한한다. 이는 confused deputy 문제를 줄이는 데 도움이 된다.

13.5 이미 권한이 있다고 나오는 경우

다음 오류가 발생할 수 있다.

ResourceConflictException: The statement id (allow-bedrock-agent-invoke) provided already exists.

이 경우 기존 정책을 확인한다.

aws lambda get-policy \
--function-name rag-lab

기존 statement를 삭제하려면 다음 명령을 사용한다.

aws lambda remove-permission \
--function-name rag-lab \
--statement-id allow-bedrock-agent-invoke

그 뒤 다시 add-permission을 실행한다.

18. 문제 해결 가이드

18.1 Agent가 Lambda를 호출하지 않는 경우

확인할 항목은 다음이다.

점검 항목설명
Action Group 설명EC2 상태 조회용 도구라는 설명이 명확한가
Function 설명현재 상태, 실행 여부, 서버 상태 질문에 사용한다고 되어 있는가
Parameter 설명instance_name이 EC2 Name 태그 값이라고 설명되어 있는가
Agent Instruction실시간 서버 상태는 get_ec2_status를 사용하라고 되어 있는가
Prepare 실행 여부설정 변경 후 Prepare를 다시 눌렀는가

18.2 Agent가 Lambda 호출 권한 오류를 내는 경우

가능한 원인은 Lambda 리소스 기반 정책이 없기 때문이다.

다시 실행한다.

aws lambda add-permission \
--function-name rag-lab \
--statement-id allow-bedrock-agent-invoke \
--action"lambda:InvokeFunction" \
--principal bedrock.amazonaws.com \
--source-arn"arn:aws:bedrock:ap-northeast-2:[계정ID]:agent/[에이전트ID]"

18.3 Lambda는 실행되지만 EC2 조회가 실패하는 경우

가능한 원인은 Lambda 실행 역할에 EC2 권한이 없기 때문이다.

다시 실행한다.

aws iam attach-role-policy \
--role-name [함수_역할_이름] \
--policy-arn arn:aws:iam::aws:policy/AmazonEC2ReadOnlyAccess

18.4 Knowledge Base 답변이 나오지 않는 경우

확인할 항목은 다음이다.

점검 항목설명
KB 연결 여부Agent에 Knowledge Base가 추가되어 있는가
KB Sync 여부문서 업로드 후 동기화했는가
문서 내용정기 패치 일정 문구가 실제 문서에 있는가
KB 설명패치 일정, 운영 매뉴얼 질문에 사용한다고 작성했는가
Prepare 여부KB 연결 후 Prepare를 다시 실행했는가

19. 정리

이번 실습에서는 Bedrock Agent를 사용해 지식 기반 챗봇을 운영 기반 챗봇으로 확장했다.

핵심 흐름은 다음과 같다.

정적 문서 질문 → Knowledge Base 검색
실시간 운영 상태 질문 → Lambda 도구 호출
복합 질문 → Agent가 두 작업을 오케스트레이션

이번 실습에서 중요한 포인트는 권한 구조이다.

Lambda 실행 역할 권한
→ Lambda가 EC2를 조회하기 위한 권한

Lambda 리소스 기반 정책
→ Bedrock Agent가 Lambda를 호출하기 위한 권한

이 구조를 이해하면 이후 다음과 같은 운영 자동화 챗봇으로 확장할 수 있다.

  • EC2 상태 조회 챗봇
  • S3 버킷 정책 점검 챗봇
  • CloudWatch 알람 조회 챗봇
  • 장애 대응 매뉴얼 기반 챗봇
  • 운영 상태 조회 + 문서 검색 통합 챗봇
  • FastAPI 백엔드와 연결한 사내 운영 포털형 챗봇
